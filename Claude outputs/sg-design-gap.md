# 디자인 차이 — 눈이 아니라 자로 쟀습니다

## 먼저 답

**차이는 큽니다. 다만 "많이" 가 아니라 "한 군데가 깊게" 입니다.**

구조와 문안은 시안대로 거의 다 들어가 있습니다. 시안이 지정한 문자열이
화면에 그대로 있습니다 — 「상세페이지를 붙여넣으세요.」 · 「KC 인증 · 리콜 ·
유해물질 기준을 정부 원문으로 확인합니다.」 · 「예시로 바로 확인하기」,
예시 카드 3장의 **상태 → 상황 → 한 줄 설명 → 예시 데이터** 순서, textarea
최소높이 180px, dashed 드롭존과 「PNG · JPG · WEBP · GIF / 최대 4장」,
보라 계열 subtle callout. 여기까지는 시안과 화면이 같습니다.

**어긋난 것은 하나가 압도적입니다 — 그림자입니다.**

    화면 여덟 장에서 카드로 센 것          78개
    그중 그림자가 붙은 것                   0개
    (1280px · 390px 두 폭에서 같은 수)

시안 §16 은 이렇게 적습니다 — *"MVP처럼 모든 카드에 동일한 border만 두지 말고,
배경색 + border + 약한 shadow를 조합한다."* 그리고 §21 은 Before 를
*"MVP 느낌의 단순 border 카드"* 라고 이름 붙였습니다.

**우리 화면이 지금 정확히 그 Before 입니다.**

더 나쁜 것은 — 시안의 그림자 값은 **이미 우리 토큰에 있습니다.**

    design/tokens.css:88
      --shadow-1: 0 1px 2px rgba(30,25,50,.04), 0 8px 24px rgba(30,25,50,.05);

시안 §16 의 값과 **한 글자도 다르지 않습니다.** 그런데 `app.css` 88KB 전체에서
`var(--shadow-1)` 을 쓰는 곳이 **0곳**입니다. `box-shadow` 선언 자체가 6개뿐이고,
그중 카드에 닿는 것은 `.demo:hover` 하나입니다.

    .demo:hover{ border-color:var(--primary-50); box-shadow:var(--shadow-2) }

즉 **그림자는 마우스를 올려야만 나타납니다.** 시피님이 시안과 나란히 놓고 비교한
것은 정지 캡처이고, 정지 캡처에서 우리 카드는 **언제나 평평합니다.**

## 잰 범위

결론을 좁혀 적습니다.

    대조한 시안   design/안심_소싱_돋보기_디자인_MD.md (725줄 · 커밋 aeec0fb)
    잰 화면       배포본 8장 (/ · /scan · /batch · /samples · /misses ·
                 /guide · /watch · /unknown) · 1280px 와 390px 두 폭
    잰 방법       실제 렌더 후 computed style — 소스 문자열이 아닙니다

⚠ **시피님이 보내신 시안 "이미지" 는 대조 대상에 들어 있지 않습니다.** 제가 지금
들고 있는 것은 시안 **문서**입니다. 이미지에만 있고 문서에 안 적힌 것(아이콘 배치,
입력창 모양 같은 것)이 차이의 원인이라면 아래 목록에 안 잡힙니다. 그럴 것 같으면
이미지를 한 번 더 주십시오 — 그때는 이미지를 기준으로 다시 재겠습니다.

## 실측 대조표

| 항목 | 시안 | 배포본 실측 | 판정 |
|---|---|---|---|
| 카드 그림자 | 배경+border+약한 shadow (§16) | **78개 중 0개** · hover 에만 | **고친다** |
| 섹션 사이 간격 | 48 / 64 (§14) | **40px** (`section+section{margin-top:var(--s10)}`) | **고친다** |
| 카드 모서리 | 14px 하나 (§15) | **다섯 값** — 14(36) · 12(29) · 16(7) · 20(4) · 24(2) | **정한다** |
| 컨테이너 | 1280 / padding 32 | 1248 / padding 24 → 내용 폭 **1200 vs 1216** | 안 한다 |
| 히어로 제목 | H1 36 (§3) | 32px | 안 한다 |
| 본문 | Body 14 / Body L 16 | 15px (/scan) · 17px (/samples·/guide) | 안 한다 |
| 폰트 | Pretendard | 고운돋움 + 본고딕 | **안 한다 (근거 있음)** |
| 제목 굵기 | 600 | 400 | **안 한다 (근거 있음)** |
| Primary CTA | 48px · r10 · w600 | 60px · r14 · w700 | **안 한다 (근거 있음)** |

### 「안 한다」 셋의 근거 — 이건 실수가 아니라 결정입니다

에이전트가 시안을 그대로 따르려다 이 셋을 건드리면 **이미 내린 판단을 모르고
되돌리는 것**이 됩니다. 그래서 근거를 같이 적습니다.

**폰트.** `design/README.md:69` — *"공공 디자인 시스템 폰트(Pretendard GOV)는
쓰지 않는다 — app.css 머리주석의 '정부 식별 요소를 가져오지 않는다'에 맞춘다."*
그리고 `tests/test_static_cache_and_font.py:112` 가 `"Pretendard" not in code` 로
잠가 뒀습니다. 시안은 Pretendard 기준으로 그려졌고 우리는 의도적으로 다른
글꼴입니다.

**제목 굵기.** 제목 글꼴이 **고운돋움이고 단일 굵기(400)** 입니다. 시안의 600 을
주면 브라우저가 가짜 굵기(faux bold)로 그립니다 — 글자가 뭉개집니다. 시안의 600 은
Pretendard 를 전제한 값이므로, 폰트 결정을 유지하는 한 따라갈 수 없습니다.

**CTA 높이.** `app.css:274` 에 이미 적혀 있습니다 — *"주 버튼은 랜딩과 같은
눈금이다 - 높이 60 · 글자 19 · 반경 --r-l. 도구 화면만 56 이면 같은 제품이 두
벌로 보인다."* 시안의 48 로 내리면 랜딩과 갈립니다.

**컨테이너.** 재 보니 내용 폭 차이가 **16px** 입니다(1200 vs 1216). 눈에 안 보이는
값이고, 고치면 모든 화면의 줄바꿈 위치가 한 번씩 흔들립니다. 값이 이득보다 큽니다.

## 에이전트 지시

### ① 그림자를 실제로 붙인다 — 가장 큰 한 건

`--shadow-1` 은 이미 시안 값 그대로 있습니다. **새 값을 만들지 말고 그것을 씁니다.**

대상은 "카드" 입니다 — 배경색이 있고 테두리가 있고 모서리가 둥근 덩어리.
실측으로 78개이고, 화면별 분포는 위 표와 같습니다. 클래스 이름은 화면마다
다르므로 `app.css` 에서 `border:...solid...` + `border-radius` + `background` 를
함께 가진 규칙을 찾아 붙입니다.

    box-shadow: var(--shadow-1);

⚠⚠ **다크 모드를 같이 재십시오. 지금 `--shadow-1` 에는 다크 재정의가 없습니다.**

    design/tokens.css:88   --shadow-1  라이트만 있음
    design/tokens.css:121,143  --shadow-2  다크 재정의 있음

다크 배경 위에 `rgba(30,25,50,.04)` 는 **보이지 않습니다.** 두 갈래 중 하나를
고르고 **고른 이유를 주석에 적으십시오**:

    (가) 다크에서는 그림자 대신 표면을 한 단계 밝혀 입체를 만든다 →
         `--shadow-1` 다크 값을 `none` 으로 두고, 카드 배경을 한 칸 올린다
    (나) 다크용 그림자를 따로 준다 → `--shadow-2` 가 한 것과 같은 모양으로
         `rgba(0,0,0,...)` 계열로 재정의

⚠ 이 저장소에서 **"라이트만 재고 다크는 아무도 안 봤다" 가 이미 한 번 났습니다**
  (칩 대비 1.72 · CLAUDE.md §6). 같은 자리입니다.

### ② 섹션 간격 40 → 48

    app.css:227   section+section{margin-top:var(--s10)}   /* 40px */
                → section+section{margin-top:var(--s12)}   /* 48px · 시안 §14 */

`--s12:48` 는 이미 토큰에 있습니다. 한 줄입니다.

⚠ 8장 전부에 걸리는 한 줄이므로, 고친 뒤 **8장을 같은 폭에서 다시 찍고 높이를
  적으십시오.** 장수가 아니라 높이입니다(§6).

### ③ 카드 모서리 — 값을 고르기 전에 **소유자를 정한다**

이것이 셋 중 가장 중요합니다. 지금 **문서 둘이 서로 다른 값을 적고 있습니다**:

    design/안심_소싱_돋보기_디자인_MD.md §15   Card 14px
    design/README.md:72                      카드 16(--r-xl) · 버튼 12(--r-m)

그리고 화면은 **둘 중 어느 쪽도 따르지 않고 다섯 값**을 씁니다(14 · 12 · 16 ·
20 · 24). CLAUDE.md §6 이 이걸 이름 붙여 뒀습니다 — *"같은 판단을 두 곳에 적지
마라. 조건이 갈리면 한쪽만 고쳐도 나머지가 거짓말을 계속한다."*

**에이전트가 값을 고르지 마십시오.** 대신 이것만 하십시오:

1. 두 문서 중 **어느 쪽이 소유자인지 한 줄로 제안**하고 (권고: 시안 문서 —
   시피님이 준 기준이고, README 의 16 은 우리가 나중에 적은 값입니다)
2. 진 쪽 문서에 **"모서리 값의 소유자는 ○○ 다"** 한 줄을 넣어 갈림을 없애고
3. 78개를 그 값으로 통일했을 때 **어느 화면이 어떻게 달라지는지 캡처로 먼저
   보이십시오.** 고치기 전에 봅니다.

### ④ 그림자가 다시 사라지지 않게 센다

지금 `--shadow-1` 이 0회 쓰인 것을 **아무 검사도 잡지 못했습니다.** 정의만
있고 안 쓰는 상태가 조용히 유지됐습니다.

    tests/ 에서 shadow 를 보는 검사   0건 (실측)

검사를 하나 넣되, CLAUDE.md §6 대로 **몇 개를 봤는지 같이 단정**하십시오:

    var(--shadow-1) 을 쓰는 규칙이 N개 이상이다   ← assert len(found) >= N
    그 N 이 0 이 아니다                          ← 0개를 보고 통과하면 검사가 아니다

`assert not bad` 만으로는 부족합니다. 이 저장소에서 **0개를 보고 통과한 검사가
하루에 세 번** 났습니다(§6).

처럼 섹션이 많은 화면에서 더 크게 벌어집니다. 거기도 같이 찍어 보십시오.

## 한 줄 요약

시안과 화면이 다르게 보이는 이유는 **레이아웃이 아니라 표면**입니다. 구조는
시안대로 다 들어가 있고, 빠진 것은 시안이 §16 에 적고 우리가 토큰까지 만들어
두고 **한 번도 쓰지 않은 그림자 한 줄**입니다.
