# 도매꾹 상품 리스트 — **됩니다. 그리고 이게 조회 실패를 우회합니다**

## 0. 먼저 시피님 전제 하나

> 한 번도 성공 못 했으면 결국 인증을 못 받는 거잖아?

**성공한 적이 있습니다.** 배포본(도쿄)에서요.

    2026-09-15 14:09:55Z   성공
    2026-09-18 01:55:26Z   성공  ← 작업로그: "고장이 스스로 풀렸다"
    2026-09-18 이후        9회 중 3회 실패 — "끊겼다 이어진다"
    2026-09-20 오늘        이 세션 시도 전부 실패 · 성공 0

그러니 "도쿄에서는 원리적으로 불가능" 이 아닙니다. **불안정한 것**이고,
오늘은 한 번도 안 됐습니다. 이 구분이 fly 를 버릴지 말지를 가릅니다.

⚠ 그리고 제가 앞서 "이 클라우드 컨테이너에서도 안 닿는다" 고 적었는데,
  다시 보니 **우리 쪽 프록시가 끊은 것**이었습니다
  (`ws_closed_mid_exchange`). 국외 전반의 증거로 쓸 수 없습니다. 뺍니다.

## 1. 도매꾹 상품 리스트 — 필요한 게 전부 있습니다

`docs/도매꾹_OpenAPI/참조.md §2` 에 응답 필드가 이미 적혀 있습니다.

    list.item.no        int      상품번호  → getItemView 의 no 로 이어진다
    list.item.title     string   상품제목
    list.item.thumb     string   **썸네일 URL**
    list.item.url       string   상품 URL
    list.item.price / priceOrg   가격
    list.item.unitQty   int      최소구매수량
    list.item.id / nick          판매자 아이디 / 닉네임   ← PII. 안 쓴다

그리고 **코드도 이미 있습니다** — `domeggook_client.py:150 items()` 가
`getItemList` ver 4.1 을 부릅니다. `kw`(검색어) 또는 `ca`(카테고리)로
한 번에 최대 200건, 정렬 `rd`(도매꾹 랭킹순).

⚠ 제가 처음에 수집 자료에서 `imgUrl` 을 보고 "썸네일 있다" 고 생각했는데
  **그건 인증마크 이미지**(`safetyCert[].imgUrl`)였고 값도 `-` 였습니다.
  진짜 썸네일은 `list.item.thumb` 이고, 참조 문서로 확인했습니다.

### 호출이 적습니다

    ① getItemList(ca=…, so="rd", sz=100)        1회   → 상품 100개
    ② getItemView(multiple=true, no=1,2,…,100)  1회   → 상세 100개
                                                       (최대 100개 한 번에)
    ③ 인증번호가 있는 것만 국표원 조회           ~20–30회
                                                 ────────
                                                 약 30회

도매꾹 쿼터는 **분당 180 · 하루 15,000** 입니다. 무시할 수준입니다.

## 2. 이게 왜 조회 실패를 우회하는가 — **핵심입니다**

지금 문제의 모양은 이렇습니다:

    셀러가 **아무 번호나** 타이핑한다  →  우리가 미리 조회해둘 수 없다
                                      →  실시간 조회가 필요하다
                                      →  도쿄에서 실패한다

시피님 안은 이 사슬을 끊습니다:

    우리가 **고른 상품**을 보여준다   →  그 상품의 인증번호를 우리가 안다
                                      →  **한국에서 미리 조회해 사본에 넣는다**
                                      →  클릭하면 반드시 답이 나온다

**「직접 치기보다 도매꾹 상품을 먼저 보여준다」가 그대로 해법입니다.**
우리가 이미 쓰는 구조(seed)의 확장이고, 새 설계가 아닙니다.

⚠ 그렇다고 실시간 조회가 필요 없어지는 것은 아닙니다. 셀러가 **자기 상품**을
  넣는 경로는 제품의 본체이고 거기는 여전히 조회가 필요합니다. 이 안은
  **투표·데모·첫인상을 구하는 것**이지 제품을 완성하는 것이 아닙니다.
  구분해서 적어야 나중에 "해결됐다" 고 오독하지 않습니다.

## 3. 총괄 판정 — 조심할 것 넷

### ① 판매자 정보는 저장하지 않는다 — **남길 목록** 방식으로

`list.item.id` · `nick` 이 판매자 식별자입니다. CLAUDE.md §6 이 두 방식을
비교해 뒀고, 이 경우는 **남길 목록**이 강합니다 — 우리가 쓸 필드가 다섯뿐
입니다:

    no · title · thumb · url · price        ← 이것만 남긴다
    그 밖 전부 버린다                          (id · nick · seller.* · return.* …)

> *"쓰는 필드를 셀 수 있으면 남길 목록 쪽이 강하다 — 새로 만들 때 먼저
> 이것부터 따져 볼 것."* (CLAUDE.md §6)

`mfds_pii.py` 가 본보기입니다. `domeggook_pii.write_sanitized()` 는 지울
목록이라 **새 필드가 남습니다** — 이 경로에는 새로 남길-목록 함수를 만듭니다.

### ② 리스트에 신호를 미리 칠하지 않는다

이게 가장 조심할 자리입니다. **특정 판매자의 실제 상품에 우리가 빨간불을
붙여 공개하는 것**이기 때문입니다.

지금 `/samples` 는 `cert_number · title · text · result` 만 담고 **상품번호도
URL 도 판매자도 없습니다.** 익명입니다. 시피님 안은 링크와 썸네일을 붙이므로
한 걸음 더 나갑니다.

    리스트 카드     제목 · 썸네일 · 가격 · 최소수량만. **신호 없음**
    클릭 후 결과    거기서 처음 신호를 보여준다

그리고 결과 화면에 한 줄을 답니다 (§9 고정 문구와 별개):

    "이 결과는 상세페이지에 적힌 인증번호를 정부 DB 에 조회한 것이며,
     상품이나 판매자에 대한 평가가 아닙니다."

⚠ RED 가 나오는 상품은 이 리스트에 넣지 않습니다. 빨강 사례는 지금처럼
  `/samples` 의 **익명 기록본**으로 보여줍니다 — 이미 그렇게 되어 있습니다.

### ③ 썸네일을 어디서 받을지 정한다

도매꾹 CDN 을 브라우저가 직접 받으면 **R4 「브라우저가 받는 곳」이 하나
늘고, 그건 처음으로 상거래 사이트 호스트입니다.** 지금은 둘 다 폰트입니다.

R4 의 기준을 그대로 적용합니다 — *"투표 기간에 그 호스트가 죽으면 화면이
어떻게 보이나."* 이미지가 안 뜨면 카드가 빈 상자가 됩니다. 폰트보다 나쁩니다.

    (가) hotlink       값 0. 약관 확인 필요. 죽으면 빈 카드
    (나) 우리가 받아 저장  용량↑. 약관 안전. 죽어도 뜬다
                        ⚠ 100장이면 수 MB. 리포에 넣을지 볼륨에 둘지 정한다

⚠ **이용약관을 확인하기 전에는 (가)를 쓰지 않습니다.** 상품 이미지는 판매자
  것이고, 우리가 아직 안 읽었습니다 (R5 — 확인 안 한 것을 근거로 쓰지 않는다).

### ④ 사본이 낡는다

참조 문서가 적어 뒀습니다 — *"판매중지·판매종료·품절·단종은 결과에 포함되지
않는다."* 즉 **목록에 나온 순간에는 판매중**이지만, 사본을 저장하면 시간이
지나며 품절됩니다.

    화면에 "2026-09-20 기준 도매꾹 판매중 상품" 을 적는다
    클릭하면 도매꾹 원문으로 갈 수 있게 한다 (url 필드가 있다)

## 4. fly 를 버릴 것인가 — **지금은 아닙니다**

### 옮기기 전에 안 잰 것이 둘 있습니다

    ① 타임아웃이 원인인가
       `kats_client.py:518  timeout: float = 8.0`
       한국 0.39s · 도쿄 8초 초과. 8초가 짧지는 않지만,
       **30초를 주면 되는지 아직 안 쟀습니다**

    ② 도쿄만인가 국외 전반인가
       미완 §1-p 가 재려다 멈춘 자리입니다. 싱가포르에서 한 번 재면 갈립니다
       ⚠ **별도 앱**으로 잽니다. 프로덕션 앱에 머신을 붙이면 위험합니다

①이 원인이면 **한 줄 고치고 끝납니다.** 그걸 안 재고 플랫폼을 옮기는 것은
비쌉니다.

### Vercel 은 그대로 못 받습니다

우리 앱은 이렇습니다:

    /data/watchlist.db      영속 볼륨
    sync_loop               백그라운드 상시 태스크
    FastAPI                 상주 프로세스

Vercel 은 서버리스라 **영속 디스크가 없고 백그라운드 루프가 돌지 않습니다.**
옮기려면 워치리스트 저장과 동기화 루프를 다시 설계해야 합니다 — 투표 전날에
할 일이 아닙니다.

⚠ Vercel 에 서울 리전(icn1)이 있는지, 있다면 **함수의 아웃바운드 IP 가
  한국인지**는 제가 확인하지 않았습니다. 리전이 있다고 나가는 IP 가 한국인
  것은 아닙니다 — 옮기기로 하면 그것부터 잽니다.

### 한국 리전이 필요하면 더 싼 길이 있습니다

    fly 는 그대로 두고 **한국에 조회 중계 하나만** 둔다
      → `kats_client` 의 base URL 하나만 바꾼다
      → 볼륨 · 도메인 · 환경변수 · 배포 전부 그대로
      → 실패해도 되돌리기가 한 줄이다

앱 전체를 옮기는 것과 비교가 안 됩니다.

### ⚠⚠ 그리고 날짜를 봅니다

**투표가 내일(9/21)부터 10/5 까지 18일입니다.** 배포 구조를 투표 전날에
바꾸면, 조회가 가끔 실패하는 것보다 **서비스가 통째로 죽는 것**이 훨씬
비쌉니다. 그리고 §3 의 안이 **투표 기간 동안 조회 실패를 안 보이게 만듭니다.**

    지금 (9/20~21)   §3 리스트 + 문구 수정 + 사본 갱신
    투표 중           관측만 한다 (실패율을 매일 본다)
    10/5 이후         ①② 를 재고, 그 결과로 플랫폼을 정한다

## 5. 순서

    1. 문구 수정 (sg-lookup-honesty.md §3) — 원인을 말하지 않는 쪽으로
    2. 리콜 사본 · seed 갱신 — 시피님 컴퓨터에서
    3. **도매꾹 리스트** — 아래 순서로
       a. 이용약관에서 이미지·데이터 사용 조건을 읽는다 (③)
       b. 남길-목록 정제 함수를 만든다 (①)
       c. scripts/ 에서 상품 N개를 받아 사본을 만든다 (한국에서)
       d. 그 상품들의 인증번호를 국표원에 조회해 seed 에 넣는다
       e. 화면: 리스트(신호 없음) → 클릭 → 결과
    4. 타임아웃 시험 ①  — 별도 앱으로
    5. 국외 지점 시험 ② — 별도 앱으로
    6. 플랫폼 결정      — 4·5 의 결과를 보고

⚠ 3-a 가 먼저입니다. 약관을 안 읽고 이미지를 가져오면, 고쳐야 할 때
  화면 전체를 다시 만들어야 합니다.

## 한 줄 요약

호출 30회면 100개를 채웁니다. 그리고 그게 **조회 실패를 우회합니다**:
우리가 고른 상품은 한국에서 미리 조회해 사본에 넣을 수 있으니까요.
**fly 를 버리는 것은 그 다음이고, 타임아웃 8초부터 재본 뒤입니다.**
