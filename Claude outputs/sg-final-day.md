## 0. 계획을 바꾸는 사실 둘 — 먼저 읽는다

### (1) 인증 조회가 **다시 죽어 있다**

    kats.last_success_at     2026-09-18 07:20Z   ← 하루 넘게 성공이 없다
    kats.consecutive_failures 2 · failure_rate 0.455
    sync.last_sync_error     "timed out" (국내·국외 둘 다)

이번엔 이름 풀이가 아니라 **연결 시간 초과**다. 우리가 고칠 수 있는 자리가 아니다.

### (2) 데모가 지금 살아 있는 이유는 **메모리 캐시** 하나다

빨강 데모를 지금 넣으면 이렇게 온다.

    인증번호 'CB067R317-5002'가 조회되었습니다(인증상태: 적합).
    (조회 서비스에 연결하지 못해 2026-09-18 조회분으로 표시합니다.
     최신 상태는 근거 링크에서 확인해 주세요.)

`CertCache` 는 `dict` 다 — **프로세스 메모리**다. `/healthz` 도 "재배포하면 0" 이라
적어 둔 그 자리다. **그러니 지금 배포하면 캐시가 날아가고, KATS 가 죽어 있으니
데모 셋이 전부 "조회 실패" 로 뜬다.** 투표 전날에.

**→ 오늘 밤 어떤 배포도 §1 의 안전장치 없이는 안 한다.** 이게 이 문서의 첫 규칙이다.

### 시간

    지금       9/19(토) 21:55 KST
    제출 마감   9/20(일)
    투표       9/21 ~ 10/5

시간을 이유로 빼는 항목은 없다. **빼는 항목은 검증이 불가능한 것뿐이다** (§5).

## 1. 선행 조건 — 인증 조회 캐시를 **시작 시 시드**한다

배포해도 데모가 살아 있게 만드는 가장 작은 변경이다.

    무엇      데모 3 + 체험 표본(§2-B)의 인증번호에 대한 **이미 조회된 결과**를
             fixture 로 담아, 앱 시작 시 `CertCache` 에 넣는다
    어디      `sourcing_guard/data/cert_seed.json` (Dockerfile 이 담는 폴더)
             각 항목: 번호 · 레코드 · **fetched_at (실제 조회 시각)**
    어떻게    `_lifespan` 에서 `kats._cert_cache.put(...)` — 기존 API 그대로
    stale    시드된 항목은 TTL 이 지났으므로 `stale=True` 로 나온다 →
             화면이 **"YYYY-MM-DD 조회분으로 표시합니다"** 라고 말한다. 그게 맞다

### 왜 R5 위반이 아닌가

값을 지어내지 않는다 — **실제로 조회해서 받은 레코드**를, **실제 조회 시각**과
함께 보관하는 것이다. `verifier.py:1289` 가 그 시각을 화면에 적는다. 정부 API 가
살아 있으면 캐시를 갱신하고 죽어 있으면 시드를 쓴다. 지금 프로세스 메모리에
있는 것과 **같은 정보를 같은 규칙으로**, 재시작을 건너게 하는 것뿐이다.

### 검사

    · 시드 파일의 모든 번호가 `CERT_NUMBER_RE` 형식인가
    · 시드 파일의 fetched_at 이 전부 과거 ISO 시각인가 (미래·빈칸이면 실패)
    · 앱 시작 직후 `len(kats._cert_cache)` == 시드 수
    · **반대 방향**: 시드를 빼고 KATS 를 목으로 죽이면 데모가 `lookup_failed` 로 떨어지는가

### 시드 재료를 어디서 얻나

KATS 가 죽어 있으니 **지금 프로세스 메모리에 있는 캐시가 유일한 사본**이다.
배포 전에 꺼내야 한다.

    ① `/healthz` 나 관리 엔드포인트로 캐시 내용을 덤프하는 길이 있으면 그걸로
    ② 없으면 — 데모 3 번호의 레코드는 **fixtures 에 이미 있다**
       (`demo_amber_result.json` 의 kc_verified 줄 · 도매꾹_AB 의 statement)
       거기서 번호 · 인증상태 · 제품명 · 그날 시각을 그대로 옮긴다
    ③ 체험 표본 번호는 KATS 가 살아나는 순간 조회해서 넣는다.
       **살아나지 않으면 표본에서 뺀다** — 시드 없는 번호를 표본에 넣지 않는다

⚠ **①②③ 어느 것도 값을 손으로 쓰지 않는다.** 옮기는 것이다.

## 2. 심사위원 설득 — 값이 큰 순서. 전부 판정 경로 0줄

### A. 유해물질 14줄을 한 줄로 접는다  ← 가장 크다

    지금  결과 19줄 중 hazard_rule_applies 14줄, 전부 UNKNOWN → "모름투성이"
    뒤    "어린이제품 공통안전기준 14개 항목이 적용됩니다 — 펼쳐 보기" 1줄
          펼치면 지금 14줄이 **그대로** (수치 · 원문 링크 · 신호 전부)

판정 0줄. 다섯 숫자 무변화. 같은 정보를 어떻게 쌓는가만 바뀐다.
⚠ 접힌 상태에서도 **몇 개인지**와 **원문 링크 하나**는 보이게. 숨기는 게 아니다.

### B. 체험 표본 8~10개  ← 방문자가 실패 쪽을 밟을 확률을 줄인다

    재료    235건 중 **검수된 정답 104건**에서 품목이 서로 다른 것
            (완구만 있으면 "완구 전용" 으로 읽힌다 — 섬유·전기·가방·생활용품을 섞는다)
    조건    §1 시드가 있는 번호만. 시드 없는 번호는 데모에 못 넣는다
    화면    지금 데모 셋 자리를 늘린다. `/api/v1/demos` 단일 출처 그대로
    정직    옆에 이 문장을 **반드시** 둔다:
            "여기 있는 것은 저희가 맞힌 예입니다. 실상품 135건 기준 품목 적중
             104건(77.0%)이고, 틀린 8건과 못 맞힌 19건도 저장소에 공개돼 있습니다."

### C. "우리가 틀린 것" 페이지  ← 이 제품만 할 수 있는 것

    내용    오답 8건 · 미매칭 19건 · 애매 4건 — **이미 fixtures 에 있는 표**
            각 줄: 상품명(공급사·상호 제거) · 우리가 말한 것 · 맞는 것 · 왜 틀렸나
    왜      심사위원은 정확도 99% 를 믿지 않는다. **틀린 것을 내놓는 팀**은 믿는다.
            "모르면 모른다고 말한다" 가 우리 논리이고, 이 페이지가 그 증거다
    ⚠      도매꾹 상호·공급사명·연락처는 **한 글자도** 안 나간다 (`domeggook_pii`)
    ⚠      §9 단정 금지는 여기도 적용 — "고치겠습니다" 는 되고 "고쳤습니다" 는 안 된다

### D. 랜딩 대비 한 컷 — "인증번호만 보면 vs 우리"

    왼쪽   인증번호 조회 결과 하나: "적합"
    오른쪽 우리 결과: "적합 — 그러나 2026-07-23 리콜"
    코드 거의 없음. 스토리다. 커버 이미지의 문장을 화면에 옮기는 것

### E. 실제로 알린 사례 — 있으면 랜딩에 한 줄

`alerts_stored: 2`. **그 두 건이 진짜 셀러 항목인지 우리 시험인지** 프로덕션 DB 에서
확인한다(볼륨에 있어 로컬에선 못 본다). 진짜면 "이 서비스가 실제로 알린 리콜 N건"
한 줄이 R6 약속의 증거다. 시험이면 **적지 않는다.**

### F. 작은 것 둘 (같은 배포에 태운다)

    · 320px 히어로 — 그리드 아이템 `min-width: 0` (픽셀을 깎지 않는다 · §1-l)
    · 파비콘 viewBox 정사각 (`0 0 64 64`) — 면적 +31%

## 3. ⚠ 장애를 **숨기지 말고 보여 준다** — 이게 발표의 핵심이 될 수 있다

KATS 가 투표 중에 죽어 있을 확률이 높다. 대부분의 서비스는 그때 둘 중 하나다 —
옛 값을 조용히 보여 주거나, 깨진다. 우리는 **셋째**를 한다:

    "조회 서비스에 연결하지 못해 2026-09-18 조회분으로 표시합니다.
     최신 상태는 근거 링크에서 확인해 주세요."

**정부 API 가 답하지 않을 때조차 우리는 언제 조회한 것인지 말한다.** 이 문장을
시연영상에서 **일부러 보여 준다.** "저희 데이터 출처가 지금 이 순간 답하지 않고
있습니다. 그래도 화면은 거짓말을 하지 않습니다" — 심사위원에게 이보다 센 문장은
없다. 결점을 감추는 팀이 아니라 결점을 설계한 팀으로 보인다.

⚠ 단 §9: "거짓말을 하지 않습니다" 는 우리 동작에 대한 사실이라 쓸 수 있다.
  "안전합니다" 류는 여전히 금지.

## 5. 하지 않는 것 — 이유는 시간이 아니다

    ✗ 추출 프롬프트 변경 · 여러 상품 감지 · 매처 보강 · 미매칭 19 줄이기
      → 전부 **235 재측정**을 부른다. 재측정하면 다섯 숫자가 움직이고, 움직인 수를
        **검증할 시간이 없는 게 아니라 검증할 방법이 오늘 밤엔 없다** — 사람 검수가
        들어가는 수다. 마지막 날에 검수 안 된 수를 발표 숫자로 쓰지 않는다
    ✗ 결과 공유 링크
      → 결과를 저장해야 하고, page_text 에 셀러가 붙인 상세페이지가 그대로 들어 있다.
        저장 = 개인정보 경로 하나 새로 만드는 것. 마지막 날 일이 아니다
    ✗ 랜딩에 "인증 조회 정상" 같은 상태 표시
      → 지금 죽어 있다. 살아 있을 때만 참인 문장을 화면에 두지 않는다 (§9)
    ✗ 태그 · 이력 재작성
