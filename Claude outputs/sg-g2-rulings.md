## 1. 커밋 정리 — **합쳐라.** 그리고 규칙을 좁힌다

`ac61bde`(G0) 가 파일 여섯을 CRLF 로 바꿨고 `bc7b69f` 가 되돌렸다. 둘 다 **푸시 전**이다.

### 판정: `bc7b69f` 를 `ac61bde` 에 squash 한다

    이유    kats_client.py 의 blame 이 1,000줄을 시드 커밋으로 가리키는 건 이 파일을
           만질 모든 사람이 영구히 내는 세금이다. 지금 안 합치면 못 합친다
    방법    rebase -i 로 둘을 하나로 · d87b951 은 그대로 위에
    확인    합친 커밋의 diff 가 **메서드 하나 + 시드 배선**만인가 (2,119줄이면 실패)
           `git ls-files -z | xargs -0 file | grep -c CRLF` → 0
    메시지   `newline=""` 교훈은 커밋 메시지에 남긴다 — 되돌린 커밋이 사라지므로

### §6 의 그 규칙은 **공유 이력**을 지키는 것이다

"커밋 되돌리기는 총괄 확인 없이 하지 않는다" 를 네가 넓게 읽었다. 좁혀 적어 둔다:

    ✗ 푸시된 커밋 · 태그 · 브랜치 이력  → 총괄 확인 필수
    ✓ 푸시 전 로컬 커밋의 squash · amend · reorder → 네 판단으로 한다

CLAUDE.md §6 에 이 두 줄을 넣어라. 묻는 것 자체는 옳았다 — 다음엔 안 묻게.

### 재발 방지 — 스크립트가 아니라 저장소가 막는다

CRLF 가 생긴 이유는 **오늘 기계가 Windows** 라서다 (어제는 macOS). `newline=""` 은
그 스크립트 하나만 고친다.

    .gitattributes    `* text=auto eol=lf`  ← 어느 기계에서 커밋해도 저장소는 LF
    git config        이 리포에서 `core.autocrlf false` 확인
    검사              `test_no_crlf_in_tracked_text` — 추적 파일에 CRLF 0건

⚠ 첫 측정(`grep -c $'\r'` 가 LF 블롭에 1047)이 틀렸던 것도 같은 뿌리일 가능성이
  크다 — Windows 파이프가 CR 을 넣는다. **줄끝은 바이트로 센다** 는 네 결론이 맞다.

### 구성이 좋다

적합 → 만료 → 취소 순서 · 첫 카드 초록(봉제인형) · 품목 여덟 종 · 상호 제거 ·

(6번째 항목이 320px 을 되돌린다) — 전부 맞다.

**적합 5개가 전부 전기용품이라 초록이 0이었던 것을 스스로 잡아 바꾼 것** — 그게
이 표본의 목적을 정확히 이해한 것이다.

### (1) UNKNOWN 4개는 그대로 둔다. **단 A 가 선행이다**

충전기 · 방석 · 청소기 · 주전자가 UNKNOWN 인 이유는 전기용품 유해물질 기준이
미수록(§1-c · 본선)이라서다. **그건 정직한 회색이다** — 인증은 확인했고(만료 · 반납
까지 잡았다) 유해물질은 우리가 모른다고 말한다. 표본에서 빼지 않는다.

다만 §0 대로 **A(접기)가 없으면 그 네 카드가 회색 14줄로 보인다.** A 가 먼저다.

### (2) `반납` → UNKNOWN 인 이유 — **본선 질문으로 적어라**

전기주전자 `SU071354-12001` 이 "반납" 인데 신호가 UNKNOWN 이고, 기간만료는 AMBER 다.
R3 대로 모르는 상태 문자열을 초록으로 반올림하지 않은 것이니 **지금 동작은 맞다.**
그런데 "반납" 이 인증을 자진 반납한 것이면 만료와 같은 무게일 수 있다.

    지금    안 건드린다 — 상태 문자열 매핑은 판정 경로다
    본선    국표원 안내에서 "반납" 의 뜻을 확인 → 만료와 같이 볼지 정한다 (R5-b · 고시가 정한다)
    미완    §1-n 로 한 줄. "표본 중 반납 1건이 UNKNOWN — 뜻 확인 전엔 회색이 맞다"

### 제조사명 둘을 남긴 판단 — 맞다

국표원 등록 원부의 값이고 우리가 링크하는 정부 페이지에 그대로 있다. 도매꾹 공급사가
