## 2. 우리가 파는 것 — 한 문장

**"인증번호만 보면 통과합니다."**

인증이 "적합" 인 기차놀이가 2026-07-23 에 리콜됐다. 인증번호 하나만 조회하는 셀러는
이걸 놓친다. 우리는 인증·리콜·유해물질·품목 등급을 **한 번에, 정부 원문으로** 본다.

그리고 두 번째 문장이 더 중요하다:

**"모르면 모른다고 말합니다."**

정확도 99% 를 파는 서비스는 많다. 틀린 것을 공개하고, 못 받아 온 갱신을 갱신이라
부르지 않고, 정부 API 가 죽었을 때 "2026-09-18 조회분으로 표시합니다" 라고 화면에
적는 서비스는 없다. **이게 우리 자리다.**

## 3. 약점과 길 — 여덟 개

### ① 정부 API 가 불안정하다 — 지금 이 순간도 죽어 있다

    사실    9/15~18 사흘 장애 → 스스로 회복 → 9/19 다시 시간 초과. 우리가 고칠 자리가 아니다
    지금    데모는 살아 있다 — 24시간 캐시가 "9/18 조회분으로 표시" 라고 말하면서 답한다
    오늘 밤  **캐시를 시작 시 시드**해서 재배포에도 데모가 살게 한다 (sg-final-day §1)
    본선    캐시를 SQLite 로 영구화 · 조회 성공률을 화면 하단에 그대로 보인다
    발표    **이걸 숨기지 않고 보여 준다.** "출처가 답하지 않아도 언제 조회한 것인지
           말합니다" — 결점을 설계한 팀으로 보인다. §4 참조

### ② 77% 가 낮아 보인다

    사실    실패 31건 중 19건은 침묵, 8건만 오답. "넷 중 하나가 틀린다" 가 아니다
    지금    발표 문장을 바꾼다 — "오답 5.9% · 침묵 14.1% · 없는 의무 0건"
    오늘 밤  체험 표본 8~10개 (검수된 정답 중 품목이 다른 것) → 방문자가 실패 쪽을 밟을 확률↓
    본선    침묵 19 는 별칭·매처 보강으로 (싸고 위험 낮다)
           오답 8 은 추출 프롬프트 개선 → **235건 재측정** → 다섯 숫자 전/후 공개
    발표    **"우리가 틀린 것" 페이지를 공개한다.** 오답 8 · 미매칭 19 · 왜 틀렸나.
           이 페이지 하나가 정확도 숫자보다 신뢰를 더 만든다

### ③ 화면이 "모름" 투성이로 보인다

    사실    결과 19줄 중 14줄이 유해물질 기준 나열 — "모른다" 가 아니라 **적용되는 기준표**다
    오늘 밤  14줄을 한 줄로 접는다 — "공통안전기준 14개 항목 적용 · 펼쳐 보기".
           판정 0줄 변경. 19줄 → 6줄. 체감이 완전히 달라진다
    본선    "모름" 을 셋으로 가른다 — 정부에 없다 / 셀러가 안 적었다 / 우리가 못 읽었다.
           같은 회색이 아니다. 각각 다음 행동이 다르다

### ④ 실제 상세페이지는 74% 가 이미지다

    사실    도매꾹 상세 100건 중 74건이 이미지뿐. 인증 정보가 글로 있는 건 2건
    지금    **Ctrl+V 캡처 경로가 있다** — 최대 4장, 이미지에서 읽은 번호는 자동 조회하지
           않고 셀러에게 확인시킨다 (0/O 오독으로 정상 인증이 "미조회" 가 되는 걸 막는다)
    본선    실제 도매꾹 상세 이미지 10~20장으로 추출 정확도 측정 → 프롬프트 튜닝
           이미지에서 읽은 번호를 **셀러가 한 번 눌러 확정**하면 자동 조회로 넘기는 흐름
    발표    "붙여넣으세요" 대신 **"캡처해서 붙이세요"** 를 앞에 둔다. 주 경로가 그쪽이다

### ⑤ 여러 상품을 붙이면 한 상품으로 합쳐진다

    지금    "한 상품씩 넣어 주세요 — 한쪽 기준으로만 결과가 나옵니다" 안내 (오늘 배포)
    본선    추출기에 "상품이 여럿인가" 필드 → 감지 → "둘로 나눠 검사하시겠어요?"
           ②의 프롬프트 개선과 **같은 재측정에 태운다** (한 번 재고 둘을 닫는다)

### ⑥ 범위가 전안법 물품으로 좁다

    사실    식품·화장품(식약처) · 생활화학제품(환경부) 은 "범위 밖" 으로 안내만 한다
    지금    범위 밖을 **정확히 범위 밖이라고 말한다** — 해커톤에서 이건 약점이 아니라
           "어디까지 책임지는지 아는 팀" 이다
    이미    식약처 회수 376건을 수집해 뒀다 (화면 미연결 · 개인정보 필드 제거 완료)
    본선    식약처 연결 → "식약처 등록일 기준" 문구로 · 환경부는 초록누리 파일 데이터를 수집
    발표    확장 경로가 **이미 절반 와 있다**는 것을 한 줄로 — "식약처 376건 수집 완료, 연결 대기"

### ⑦ 리콜 알림이 실제로 울렸다는 증거가 약하다

    사실    감시 항목 6개 · 저장된 알림 2건. 그 2건이 실사용인지 시험인지 확인 필요
    지금    프로덕션 DB 확인 → 실사용이면 랜딩에 "실제로 알린 리콜 N건" 한 줄
    본선    셀러 커뮤니티에서 감시 항목 등록을 받는다 → 첫 실제 알림 사례를 만든다.
           **이게 제품의 유일한 약속(R6)의 첫 증거**가 된다
    발표    "저장해 두면 새 리콜과 매일 대조합니다" — 문구는 이미 정직하게 고쳤다

### ⑧ 기준표가 11월 1일에 낡는다

    사실    운용요령 개정판 시행 2026-11-01. 등급표 596건은 현행 기준. 데모데이 2주 뒤

### 덤 — "1인 + AI" 팀이라는 것

    **AI 가 판정하지 못하게 만든 것이 이 제품의 설계다.** 심사위원이 AI 챔피언십에서
