# [총괄 지시] 「모름이 나왔어요」 — **오늘 만든다.** 본선은 계산에 안 넣는다

시피님 판정이다. 투표가 본선을 정하는데 투표에 쓸 것을 본선으로 미루면 안 된다.

---

## 0. 왜 이게 남은 것 중 제일 큰가

    135건 중 19건(14.1%)이 "모름" 으로 떨어진다
    심사·투표에서 나올 첫 질문이 **"모른다고만 하는 서비스 아니냐"** 다
    그 답이 지금 **코드 안에는 있는데 화면 한 장에 모여 있지 않다**

사유별 문구도, 무엇을 물으면 되는지도, 답하면 무엇이 열리는지도 전부 있다.
**흩어져 있는 것을 모으는 일**이지 새로 만드는 일이 아니다.

## 1. ⚠⚠ 문장을 새로 쓰지 않는다 — 서버가 준다

이미 있는 것:

    scorer._UNKNOWN_HEADLINE_FIRST     소관 밖 · 연령 대상 아님
    scorer._UNKNOWN_HEADLINE           일부만 확인 · 조회 실패
    scorer._UNKNOWN_NO_INPUT           입력을 못 읽음
    scorer._absence_expected_headline  번호 부재가 정상 (계산값)
    scoping.missing_inputs()           재질 · 대상연령 · 품목 구분 (+ unlocks)

**페이지가 이 문장을 다시 적으면 두 벌이 된다.** 한쪽만 고쳐질 때 화면이
낡은 말을 한다 — 오늘만 세 번 본 모양이다.

### 상수 모양을 바꾼다 (같은 문자열, 구조만)

지금 `list[tuple[FindingKind, str]]` 이라 제목과 본문이 한 문자열에 붙어 있다.
페이지는 제목을 따로 써야 하므로 쪼개되, **쪼갠 것을 다시 합치면 지금과
한 글자도 달라지지 않아야 한다.**

```python
@dataclass(frozen=True)
class UnknownReason:
    kind: FindingKind | None
    title: str                       # "본 서비스 범위 밖"
    body: str                        # "식품·화장품 등은 … 확인하세요."
    unlocks: tuple[str, ...] = ()    # 답하면 열리는 축

# 헤드라인 = f"{reason.title} — {reason.body}"
```

⚠⚠ **검사가 이걸 잠근다.** 기존 헤드라인 다섯 개의 **완전한 문자열**을
  검사에 그대로 적어 두고, 쪼갠 뒤 합친 값이 그것과 같은지 단정한다.
  이 검사가 없으면 리팩터가 조용히 문구를 바꾼다.

⚠ `_absence_expected_headline` 은 계산값이라 상수로 못 옮긴다.
  페이지의 ③ 칸 설명은 **새 문장 하나**를 쓴다 (§3 에 준다. §9 검사 대상).

⚠ `missing_inputs` 는 이미 구조가 있다. 페이지는 **빈 입력**으로 불러
  셋을 다 받는다: `missing_inputs(materials=[], target_age=None,
  category=ItemCategory.UNCLASSIFIED)`. 문구를 손으로 안 적는다.

## 3. 화면 `/unknown`

제목: **왜 "모름" 이 나왔나**

칸마다 셋을 적는다 — **무슨 뜻 / 무엇을 하면 / 무엇이 열리나.**

```
① 소관이 다릅니다                      OUT_OF_SCOPE
   열리나  ✗  이건 저희가 **판단을 한 것**입니다

② 연령 기준으로 어린이제품 대상이 아닙니다   AGE_OUT_OF_CHILD_RANGE
   열리나  ✗  이것도 판단한 것입니다

③ 인증번호가 없는 것이 정상인 품목입니다     absence_expected
   ⚠ 새 문장 하나 (§9 검사):
     "안전기준준수·공급자적합성확인 대상은 정부 조회 DB 에 번호가 없는 것이
      정상입니다. 인증번호 대신 시험성적서를 요청하세요.
      ⚠ '인증이 필요 없다' 는 뜻이 아닙니다 — 제조·수입자에게 스스로 시험해
      확인할 의무가 있습니다."
   열리나  ✗  번호로는 안 열립니다. 서류로 확인합니다

④ 어떤 품목인지 못 알아냈습니다   ← 19/135    info_request(품목 구분)
   열리나  ✅ **품목이 정해지면 등급과 유해물질 기준이 함께 열립니다**

⑤ 재질 · 대상연령이 안 적혀 있습니다          info_request
   열리나  ✅ 화면에서 바로 답하실 수 있고, 답하면 유해물질 축이 열립니다

⑥ 정부 조회에 연결하지 못했습니다             LOOKUP_FAILED
   열리나  ✅ 잠시 후 다시 시도하면 열립니다

(⑦ 입력을 못 읽었습니다  _UNKNOWN_NO_INPUT — 짧게 한 줄)
```

⚠ **④⑤⑥에 ✅ 가 붙는 것이 이 페이지의 요지다.** 모름이 끝이 아니라 입구다.
  ①②③에 ✗ 가 붙는 것도 중요하다 — 그건 못 한 게 아니라 **한 판단**이다.

맺음 (새 문장 둘 · §9 검사):

> 모름은 저희가 게을러서가 아니라 상세페이지에 그 정보가 없기 때문입니다.
> 그래서 저희는 모름을 **"무엇을 누구에게 물으면 되는지"** 로 바꿔 드립니다.

맨 아래에 「공급처에 보낼 문안 복사」로 가는 안내 한 줄.

## 4. 어디서 링크하나 — **내비에는 안 넣는다**

`/samples` 가 같은 결정을 이미 했고 이유가 적혀 있다:

> 전역 내비에 넣지 않았다. 320px 내비 넘침을 2026-09-18 에 닫았고(미완 §1-l),
> 항목을 여섯째로 늘리면 그것이 되돌아올 수 있다.

**같은 이유로 안 넣는다.** 대신 질문이 실제로 생기는 세 곳에서 건다.

    · 결과 카드가 UNKNOWN 일 때 헤드라인 아래   ← 제일 중요하다
    · 랜딩의 "판정은 하지 않습니다" 칸
    · /misses 의 "아무 말도 못 한 것" 절

⚠ 결과 카드 링크는 **UNKNOWN 일 때만.** GREEN/AMBER/RED 에 붙으면
  기존 캡처 여섯 장이 바뀐다.

## 5. 인증 축 note — 같이 넣는다

`_axes` 의 cert 는 note 가 늘 빈 문자열이라 「번호 없음」이 막다른 곳이다.
유해물질 칸은 다음 행동을 말하는데 인증 칸만 안 말한다.

```
조회함       "인증상태: 적합"                            (이미 있음)
번호 없음     "공급처에 인증번호를 받으면 여기서 조회합니다"
  ⚠ 단, 부재가 정상인 품목에서는
             "이 품목은 번호가 없는 것이 정상입니다"
             ← 우산에 "받으세요" 는 틀린 안내다. 서버에서 갈린다
조회 실패     "잠시 후 다시 시도해 주세요"
번호 있고 문제  note 비움 — finding 이 말한다
```
