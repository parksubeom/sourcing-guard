## 1. 내가 틀린 곳 둘 — 같은 모양의 오류다

### (1) "참고 정보 → 여기서부터는 서류로만 확인됩니다" 는 **거짓말이 된다**

`models.py:308~327` 을 열어 보니 CONTEXT 에 들어가는 kind 가 **열셋**이다.

    kc_verified            인증번호 조회 '적합'          ← 서류 없이 **지금 확인된 것**
    recall_clear           리콜 공표 목록에 없음         ← 서류 없이 **지금 확인된 것**
    maker_other_recalls    같은 제조사의 다른 리콜
    recall_weak_match      유사 일치
    lookup_failed          조회 실패
    hazard_rule_applies    적용되는 기준               ← 내가 본 것은 **이것뿐이었다**
    … 그 외 일곱

머리말을 갈면 그 문장이 **`kc_verified` 위에도 붙는다.** "인증번호 적합" 은
서류로만 확인되는 것이 아니라 **방금 정부 DB 에서 확인한 것**이다. 우리가 가진
가장 강한 줄 위에 "여기서부터는 서류로만" 을 얹는 꼴이다.

### (2) "CONTEXT 줄의 신호 점을 뗀다" 도 마찬가지다

`kc_verified`·`recall_clear` 는 **초록 점**을 달고 있다. 떼면 확인된 두 줄이
나머지와 똑같아 보인다. `maker_other_recalls` 의 점도 같이 사라진다.
**R3 을 화면에서 뒤집는 짓**이다 — 값이 있는 것을 없는 것으로 반올림한다.

### (3) 왜 틀렸는가 — 오늘 다섯 번째다

접힌 유해물질 줄 **열네 개를 보고** "CONTEXT 가 회색투성이" 라고 썼다.
잰 것은 한 kind 이고 결론은 열세 kind 에 걸었다. §1-k 의 갱신 표기, 320px,
주입 CSS, 인증 조회, 그리고 접기 — **전부 같은 모양**이다.
§6 에 내가 넣은 줄("결론을 적을 때 잰 범위를 문장 안에 넣는다")을 내가 어겼다.

⚠ 그래서 **CONTEXT 를 둘로 쪼개는 것**(서버에 FindingGroup 하나 추가)이
  진짜 고침이다. 그건 열세 kind 를 다시 분류하고 검사를 새로 거는 일이라
  **본선이다.** 오늘 새벽에 할 것이 아니다.

## 2. 그래서 오늘 맞는 것 — **접힌 줄 하나**

`hazard_rule_applies` 는 `verifier.py:1774` 가 `signal=Signal.UNKNOWN` 을
**의도적으로** 붙인 것이고, 그 옆에 이유가 적혀 있다 — "이 finding 하나로
신호가 갈리면 규제 품목군이 전부 AMBER 가 된다."

    즉 그 UNKNOWN 은 **축을 안 흔들려고 고른 값**이지 화면에 내보이려고
    고른 값이 아니다. 그런데 `index.html:588` 이 그걸 회색 점으로 그린다.

이 kind 하나에만 해당하고, 코드에 이미 `isHazard(f)` 가 있다. 오너가 있다.

### 바꾸는 것 셋

    (가) 접힌 줄의 회색 점을 뺀다        index.html:588 의 `rv-dot` 한 span
         · `isHazard` 인 줄에만. 다른 CONTEXT 줄은 **손대지 않는다**

    (나) 접힌 줄 문장에 다음 행동을 붙인다    index.html:590
         지금  "…14건이 적용됩니다. 실제 함유량은 시험성적서로 확인합니다."
         바꿈  "…14건이 적용됩니다. 실제 함유량은 상세페이지로 알 수 없습니다 —
                공급처에 시험성적서를 요청하세요."

    (다) 펼치기 문구                    ⚠ **두 곳이다**
         index.html:593   최초 그릴 때
         index.html:797   토글 핸들러가 접을 때 **다시 쓴다**
         한 곳만 고치면 한 번 접었다 펴는 순간 옛 문구로 돌아간다
         바꿈  "적용되는 기준 14개 보기"  /  접을 때 같은 문구

⚠ (다)가 §6 그 자체다. 같은 문자열이 두 곳에 있다. **상수 하나로 빼라** —
  `function foldLabel(n){ return "적용되는 기준 " + n + "개 보기"; }` 하나를
  두 곳이 부른다. 고치는 김에 오너를 만든다.

### 검사 (반대 방향까지)

    · 접힌 줄에 `rv-dot` 이 **없다**. 그리고 `kc_verified` 줄에는 **있다**
      ← 두 번째 단정이 없으면 (2)의 오류를 검사가 못 잡는다
    · 펼치기 문구가 최초 렌더와 **토글 후 둘 다** 새 문구다
    · 부정 단언 검사(`test_no_verdict_language_in_ui_copy`)는 그대로 통과
    · 다섯 숫자 무변화 · 판정 0줄

## 3. 「요청 문안 복사」 — **설계를 바꾼다**

내 초안 §3 은 문안을 **새로 썼다**("이 품목은 세부품목 등급표에서 '완구 ·
안전확인 대상' 으로 조회됩니다"). 틀린 설계다. 새 문장은 §9 검사를 따로
받아야 하고, finding 이 바뀌면 조용히 어긋나고, 완구 말고 다른 품목에서
깨진다.

**바른 설계 — 화면에 이미 있는 `statement_ko` 를 그대로 인용한다.**

```
[상품명] 사입을 검토 중입니다. 아래를 보내 주실 수 있을까요?

· 안전확인신고증 사본 (신고번호 포함)
· 유해물질 시험성적서

확인한 내용 (안심 소싱 돋보기 · YYYY-MM-DD HH:MM 조회)
  - <finding.statement_ko>          ← 그대로. 한 줄도 다시 쓰지 않는다
    근거: <source_label> <source_url>
  - <finding.statement_ko>
    근거: <source_label> <source_url>
  …
```

이렇게 하면 공짜로 따라오는 것 넷:

    · **새 사실 0** (R5). 화면에 없는 문장이 클립보드에 안 들어간다
    · **§9 검사 자동 통과.** 이미 화면 문자열이고 검사는 파일 전체를 훑는다
    · **근거 없는 줄 0** (R2). `source_url` 이 문장마다 따라간다
    · 완구·생활용품·전기용품 **전부** 동작한다. 품목별 분기 0

⚠ 조회 시각·인증번호·'적합' 은 이미 `kc_verified.statement_ko` 안에 있다
  (`verifier.py:1271`). 조회가 캐시였으면 그 문장이 스스로 "조회 서비스에
  연결하지 못해 YYYY-MM-DD 조회분으로" 라고 말한다 (`verifier.py:1289`).
  **우리가 손으로 적을 것이 하나도 없다.**

### 구현이 작다 — 이미 있다

`index.html:774` 의 `[data-copy]` 핸들러가 **범용**이다. 속성에 문자열을
넣고 버튼만 그리면 끝이다. 새 JS 는 사실상 0 이다.

⚠ 다만 그 핸들러의 대체 경로가 주석과 다르다. 주석은 "선택 상태로 남긴다"
  인데 코드는 `done(false)` 로 "복사하지 못했습니다" 만 띄운다. 상품명이면
  손으로 치면 되지만 **물질 열네 개짜리 문안은 못 친다.** 이 버튼에는
  실패 시 `<textarea readonly>` 를 펼쳐 직접 고르게 해라. 그게 유일한 새 코드다.

## 7. 세 가지 — 에이전트 보고에 대한 판정

### (1) icn 리전은 **내가 틀렸다**

`Region 'icn' cannot host your machine` — Fly 의 Asia Pacific 은 sin·syd·nrt
뿐이고 **서울은 플랫폼에 없다.** 내가 본선 처방으로 올린 것이 애초에 불가능한
동작이었다. 물린다.

### (2) 싱가포르 탐침을 멈춘 것 — **맞는 판단이다**

네 말 그대로 적어 둔다.

    "고치는 방법(서울 리전)이 Fly 에 존재하지 않으므로 더 재도 행동이 안 바뀐다"
    "배포 당일 밤에 프로덕션 앱에 머신을 만드는 것은 값에 비해 위험이 크다"

**행동이 안 바뀌는 측정을 멈추는 것이 §8 그 자체다.** 그리고 `fly machine run
--command` 가 기본 CMD 를 돌려 볼륨 없는 인스턴스가 프로덕션에 붙은 것을
바로 알아채고 지운 뒤 nrt 1대·`watched 6`·격리 0 까지 되확인한 것 —
사고보다 뒷처리가 이 프로젝트의 방식이다.

### (3) `"Claude" in body` 가 "Claude Code" 에 걸려 있던 것

**오늘 가장 값이 큰 발견이다.** 검사가 통과하는데 잠그려던 것을 안 잠그고
있었다. `test_no_key_literal_is_committed` 때와 **같은 모양**이다 —
느슨한 문자열 포함 검사는 조용히 통과한다.

`settings.extractor_order` 에서 기대값을 끌어내고 런타임 표기만 보게 고친 것이
맞다. §6 에 한 줄 더할 값이 있다:

    포함 검사(`x in body`)는 **틀렸을 때 실패하는지**를 같이 단정한다.
    "있어야 할 것이 있다" 만 재면 다른 곳에 우연히 있는 것에 걸린다.
    2026-09-20: "Claude" 가 개발도구 언급에 걸려 런타임 벤더 주장이
    한 번도 안 잠겨 있었다.
