## [P1] 국표원 조회 타임아웃 — 설정으로 빼고, connect/read 를 나눠서 재 주세요

### 배경 (총괄이 오늘 실측한 것)

배포본(fly nrt·도쿄)에서 국표원 조회가 실패하고 있습니다. 그런데 **차단이
아니라 시간을 꽉 채우고 포기하는 모양**입니다.

    12:31:05Z  POST /api/v1/sync (배포본)
               → errors: domestic/overseas 둘 다 "network: timed out"
               → **전체 16.88초** = 8초 타임아웃 × 2회

    같은 시각 한국(개발 PC)에서 www.safetykorea.kr → HTTP 200 · 0.386s · 3연속
    도매꾹 API 도 한국에서 0.338s — 정상

    /healthz kats: calls 3 · failures 3 · last_success_at null

⚠ **다만 "도쿄에서 원리적으로 불가능" 은 아닙니다.** 작업로그
`docs/작업로그_2026-09-14.md:1809` 에 배포본 성공 기록이 있습니다 —
`last_success_at 2026-09-18T01:55:26Z`, 그리고 *"고장이 스스로 풀렸다 …
우리 쪽에서 바뀐 것이 없다"*. 9/18 이후로도 *"9회 중 3회 실패 — 끊겼다
이어진다"* 로 적혀 있습니다.

**그래서 이 시험이 필요합니다.** 시간을 늘리면 되는 것인지, 시간과 무관한
것인지가 갈리고, 그 답이 **fly.io 를 떠날지 말지**를 정합니다. 안 재보고
플랫폼을 옮기면 옮기고도 안 될 때 남는 것이 없습니다.

### 할 일 ①: 타임아웃을 설정으로 빼고 connect/read 를 나눈다

현재 상태:

    sourcing_guard/kats_client.py:518   timeout: float = 8.0
    sourcing_guard/kats_client.py:530   self._client = httpx.Client(timeout=timeout)
    sourcing_guard/main.py:118          KatsClient(settings.kats_base_url,
                                        settings.kats_service_key,
                                        mock=settings.mock_mode)
                                        ← timeout 을 안 넘긴다 → 기본 8.0 고정

바꿀 것:

    1. config 에 타임아웃 설정을 더한다 (환경변수로 읽게)
       connect 와 read 를 **따로** 둔다
    2. main.py:118 이 그 값을 KatsClient 로 넘긴다
    3. KatsClient 는 `httpx.Timeout(connect=…, read=…, write=…, pool=…)` 로 만든다
    4. **기본값은 지금과 같은 동작**이어야 한다 — 아무것도 설정하지 않으면
       8초로 돌아야 합니다. 이 커밋은 동작을 바꾸는 커밋이 아닙니다

### 할 일 ②: 실패 원인을 구분해서 기록한다

지금은 `httpx.ConnectTimeout` 과 `httpx.ReadTimeout` 이 **둘 다 `network`
하나로 뭉개집니다.** 그래서 "연결이 안 되는 것" 과 "연결은 되는데 응답이
느린 것" 을 가를 수 없습니다. 이 구분이 P1 의 답 자체입니다.

    연결이 안 된다   → 시간을 늘려도 소용없다. 경로 문제다
    응답이 느리다   → 시간을 늘리면 된다

`/healthz` 의 `kats.last_error_code` 가 둘을 구분하게 해 주세요
(예: `network.connect` · `network.read` · `network`).

⚠ **화면 문구는 이 커밋에서 건드리지 마십시오.** 그건 P2 이고 따로 갑니다.
  여기서는 로그와 `/healthz` 만입니다.

⚠ `kats_client.py:133` 주석이 *"재시도·캐시를 넣지 않는다. 남의 API 장애로
  우리를 죽이지 않는 설계는 그대로다. 추가하는 것은 **관측**뿐이다"* 라고
  적어 뒀습니다. **이 작업은 그 주석이 허용한 「관측」입니다. 재시도를 넣지
  마십시오.**

### 할 일 ③: 재고, 숫자를 적는다

배포한 뒤 환경변수로 값을 바꿔 가며 `POST /api/v1/sync` 를 칩니다.

    회차 1   현재값 (connect 5 / read 8 쯤)      ← 기준선
    회차 2   connect 10 / read 30
    회차 3   connect 10 / read 60               ← 회차 2 가 실패했을 때만

각 회차마다 이것을 적어 주세요:

    친 시각 (UTC)
    응답 전체 시간
    errors 문자열 원문
    /healthz 의 kats.last_error_code  ← **connect 인지 read 인지**
    성공했다면: 몇 초에 답이 왔는가 · new 몇 건이 들어왔는가

⚠ **성공/실패만 적지 마십시오.** 몇 초인지가 운영값을 정합니다.

### 할 일 ④: 재고 나면 운영값을 정한다

    성공했다면   답이 온 시간에 여유를 더한 값으로 **내린다.**
                측정용 30·60 을 운영에 두지 않습니다 — 셀러가 그만큼
                빈 화면을 봅니다
    ⚠ 운영값이 15초를 넘게 되면 **알려 주세요.** 그 경우 화면에 "정부 조회 중"
      표시가 필요한지 총괄이 판단합니다 (이 커밋에서 만들지 마십시오)
