## [UI] `h1` 세 줄 먼저, 그 다음 히어로를 `layout.py` 로

### 배경 — 총괄이 8화면을 재서 찾은 것

헤더·바닥글·히어로 제목 크기는 **여덟 장 전부 통일돼 있습니다.** 어제 작업이
잘 됐습니다. 갈리는 넷 중 셋(배지·랜딩 히어로·`main` 클래스)은 **설계라
고치지 않습니다.**

**하나만 결함입니다:**

    화면        h1  h2  h3
    /            1   5   0
    **/scan      0   1   3**   ⚠ h1 없음
    **/batch     0   1   2**   ⚠ h1 없음
    **/watch     0   1   0**   ⚠ h1 없음
    /guide       1   1   0
    /samples     1  10   0
    /misses      1   3  12
    /unknown     1   9   0

**세 화면이 `<h2>` 로 시작하고 그 위에 `h1` 이 없습니다.** `/scan` 은 메인
도구 화면입니다.

### ⚠ 어제 판단의 근거가 틀렸습니다 — 나무라는 것이 아니라 근거를 드립니다

어제 이렇게 적으셨습니다:

> *"태그를 맞추는 대신(**그 태그가 문서 구조상 맞습니다**) 규칙이 둘 다
> 받습니다."*

CSS 로 푼 것은 맞습니다 — 그 덕에 여덟 장이 60px 이 됐습니다. **다만 뒤의
근거가 성립하지 않습니다.** `h1` 이 **아예 없는** 페이지에서 `h2` 가 첫
제목인 것은 문서 구조상 맞지 않습니다. 위에 있어야 할 `h1` 이 비어 있기
때문입니다.

    접근성   스크린리더가 페이지 주제를 잡지 못합니다
    SEO     검색엔진이 페이지 주제를 약하게 읽습니다

⚠⚠ **그리고 총괄도 못 잡았습니다.** 어제 "히어로 8/8 60px" 만 재고
  통과시켰습니다 — **크기만 보고 태그를 안 봤습니다.** 세는 목록에 "크기" 를
  넣고 "태그" 를 안 넣은 것이고, 어제 §6 에 넣은 그 규칙을 총괄이 또
  밟았습니다.

## ① `h1` — 지금, 마크업 세 줄

    /scan · /batch · /watch 의 히어로 제목  `<h2>` → `<h1>`

CSS 는 이미 둘 다 받으므로 **스타일은 안 건드립니다.**

### 검사

    모든 화면에 `h1` 이 **정확히 하나**
    ⚠ **본 화면 수를 같이 단정**하십시오 — `assert len(checked) == 8`
    ⚠ 반대 방향도: `h1` 을 둘로 만들거나 없애면 실제로 빨강이 되는지

### 확인

    8장의 h1/h2/h3 수를 표로
    히어로 제목이 여전히 8/8 60px 인지 (태그가 바뀌었으므로 다시)
    가로 넘침 · 다크

**배포하고 확인한 뒤 ②로 넘어가십시오.** 묶지 마십시오 — 문제가 나면 원인을
가릴 수 있어야 합니다.

## ② 히어로를 `layout.py` 로 — ①이 깨끗하면

### 왜 이것인가 — **React 로 가서 얻으려던 것이 정확히 이것입니다**

총괄이 마이그레이션 가능성을 쟀습니다. 결론은 **지금은 안 한다** 인데,
이유가 여기에 걸립니다:

> 오늘 `h1`/`h2` 가 갈린 것은 **히어로가 8벌로 복붙돼 있어서**입니다.
> `layout.py` 가 히어로도 박으면 **그 갈림이 구조적으로 불가능해집니다.**
> 컴포넌트화로 얻으려던 것이 그것이고, **검사를 그대로 둔 채 얻을 수
> 있습니다.**

### 무엇을 옮기는가

`.intro` 7장이 **같은 모양**입니다 (실측):

    패딩      7장 전부 32px/24px
    구성      eyebrow · 제목 · 서브카피 · intro-art
    높이 차    281 / 294 / 302 — **내용 길이 차이이지 규칙 차이가 아닙니다**

⚠ **`/`(랜딩)의 `.lv2-hero` 는 건드리지 마십시오.** 789px 이고 구조가
  다릅니다. 마케팅 화면이라 다른 것이 맞습니다 — **7장만입니다.**

### 어떻게

머리글·바닥글을 옮긴 것과 같은 모양으로, **서버가 박습니다.**

    layout.py 가 받는 것   eyebrow 문구 · 제목(줄바꿈 포함) · 서브카피 ·
                         아트 파일 · 말풍선 문구(있는 화면만)
    박는 것               `.intro` 블록 전체 — **태그는 `h1` 로 고정**

⚠⚠ **태그를 `layout.py` 가 정하게 하는 것이 이 작업의 요점입니다.** 그러면
  ①에서 고친 것이 다시 갈릴 수가 없습니다.

⚠ 말풍선·아트가 **화면마다 다릅니다.** 없는 화면도 있는지 먼저 세어
  보이십시오 — 옮기기 전에 **무엇을 옮기는지** 목록으로.

### 검사

    `.intro` 를 직접 쓴 화면이 **0장**인지 (전부 layout 이 박는지)
    히어로 제목이 8/8 `h1` · 60px 인지
    ⚠ 본 화면 수 단정

### 확인

    8장 × 1440/1280/1024/768/390/320 · 다크
    캡처는 **높이**를 적습니다
    히어로 높이가 옮기기 전후로 어떻게 바뀌었는지 (내용이 같으면 같아야 합니다)

## ③ React / Next 마이그레이션 — **하지 않습니다**

물어보실 수 있어 이유를 적습니다. **기술적으로는 가능합니다** (HTML 3,019줄 ·
인라인 JS 1,992줄 · CSS 1,445줄 — 작습니다). 안 하는 이유는 셋입니다:

    ① **HTML·CSS 를 읽는 검사 파일이 71개**입니다. React 로 가면 전부
       렌더 기반으로 다시 만들어야 하고, **그 검사들이 이 제품이 지키려는
       것(R1~R7·§9)을 지키는 장치**입니다
    ② 배포 대상이 둘이 됩니다. **어제 경유지를 세운 밤을 생각하면**,
       배포 대상이 늘면 그런 문제도 늡니다
    ③ 화면이 8장이고 상태가 단순합니다 — 컴포넌트화 이득이 작습니다

**조건 셋 중 하나라도 충족되면 다시 봅니다:** 화면 15장 이상 · 화면에 상태가
늘 때 · 검사를 렌더 기반으로 옮긴 뒤.

⚠ **②가 그 조건을 앞당깁니다** — `layout.py` 가 반복 조각을 더 가져갈수록
  React 로 얻을 것이 줄어듭니다.
