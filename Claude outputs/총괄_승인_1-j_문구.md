## 2. 고칠 한 문장 — **"섞입니다" 가 네 실측과 안 맞는다**

네가 잰 것을 다시 보자.

    상품명이 한쪽으로 쏠림   8/10
    품목                   **언제나 하나**
    A 밖의 번호가 섞임        2/10

**8/10 은 "섞인 것" 이 아니라 "한쪽만 본 것" 이다.** 품목이 언제나 하나라는 것도
같은 말이다. "섞입니다" 는 2/10 을 설명하고 8/10 을 설명하지 않는다.

그리고 셀러에게 더 위험한 쪽이 8/10 이다. "섞입니다" 를 읽은 셀러는 "잘 보고
갈라 읽으면 되겠다" 고 생각하는데, **갈라 읽을 것이 없다 — 다른 상품은 아예
검사되지 않았다.** 그것을 말해야 한다.

### 최종 문구

```
한 상품씩 넣어 주세요. 여러 상품을 함께 붙이면 한 상품으로 합쳐져, 그중 한쪽
기준으로만 결과가 나옵니다.
(세트 · 색상 옵션처럼 구성품이 여러 개인 한 상품은 그대로 넣으셔도 됩니다.)
```

네 초안에서 바뀐 것 둘:

    ① "결과가 섞입니다"  →  "그중 한쪽 기준으로만 결과가 나옵니다"
       8/10 과 "품목 언제나 하나" 에 맞고, **다른 상품이 검사되지 않았다**는
       진짜 위험을 말한다

    ② 둘째 줄을 **괄호로** 내린다
       4.1%(상한) · 0.6%(실측)가 규칙과 같은 무게로 보이면 안 된다. 그리고
       이 hint 에는 뒤에 문장이 **둘 더** 있다 (본문 복사 안내 + 서버 접속 안내).
       네 문안대로면 한 단락에 다섯 문장이 되어 입력창 위가 벽이 된다

길이는 92자다 — 네 91자와 같다. 늘지 않았다.

### 자리 · 순서 — 네 판단대로 간다

`index.html:55` 의 `hint`, 기존 두 문장 **앞**. "한 상품씩" 이 과제의 범위를
정하고 그다음이 "그 안에 무엇을 담는가" 다. 순서가 맞다.
`/batch` 에 안 넣는 것도 맞다.

## 3. "주세요" 중복 — 그대로 간다

네가 먼저 물은 것이 맞고, **네가 권한 쪽(초안 유지)이 맞다.**
"한 상품씩 검사합니다" 는 우리 동작 서술이라 요청의 힘이 빠진다 — 네 말 그대로다.

그리고 고친 문구에서는 사이에 긴 문장과 괄호가 들어가고 `넣으셔도 됩니다` 가
끼어서 어미가 갈린다. 읽기에 걸리지 않는다.

## 4. 고칠 것 둘 — **기록이다. 배포를 막지 않는다**

### (1) ⚠ 날짜가 이틀 앞서 있다

    기록에 적힌 날짜   2026-09-20  (두 곳)
    실제 커밋          2026-09-18 13:41 KST

**제출 마감일로 적혀 있다.** 다음 세션이 "이 측정이 제출 전인가 후인가" 를
못 가린다. 이 프로젝트는 근거와 날짜를 같이 적는 것으로 돌아간다.
`2026-09-18` 로 고쳐라. 내 정정을 적은 "(2026-09-20 · 총괄)" 도 같다.

### (2) ⚠ `YU102043-24001` 을 전파번호라고 적었다 — **우리 코드가 아니라고 한다**

내가 우리 정규식에 직접 물었다.

    kats_client.py:344  CERT_NUMBER_RE
    rra_client.py:70    RF_NUMBER_RE

    번호                  KC형식   RF형식
    YU102043-24001        True    False    ← 전파가 아니다
    XU103198-23003B       True    False
    HU073519-24001        True    False
    YU101649-22001        True    False
    HJ6444-486            True    False
    R-R-Jy5-Q-108         False   True     ← 이것만 전파다

`models.py:74` 가 전파 형식을 **`R-C-… · KCC-…`** 로 적어 뒀다. `YU######-#####`
는 거기에 없다.

⚠ **결론은 안 바뀐다.** `['YU102043-24001', 'R-R-Jy5-Q-108']` 은 KC 하나 + 전파
  하나이므로 "KC 2개 이상" 에서 빼는 것이 맞다. 2건도 그대로다.

⚠ 그런데 **기록에 틀린 사실이 심긴다.** 그 예시가 "전파번호 섞임" 항목 아래
  둘 다 전파인 것처럼 적혀 있어서, 다음 세션이 `YU######` 를 전파 형식으로
  읽는다. 고쳐라:

    · 그 줄을 "KC 하나 + 전파 하나" 로 적는다. 어느 것이 어느 것인지 밝힌다
    · 판단 기준이 `CERT_NUMBER_RE` / `RF_NUMBER_RE` 라는 것을 적는다
      (사람 눈으로 가른 것이 아니라는 뜻이다)
    · ①-(2) 의 `['R-R-DKr-DC-CCCV-01', 'YU101649-22001']` 도 같다 — 전파는
      앞의 것 하나다

⚠ 그리고 **다시 재지 않는다.** 5건 각각이 {KC 1 + 전파 1} 인지 {KC 2 + 전파 1}
  인지는 네 요약으로는 못 가린다. 2건이 하한이라는 것은 이미 적혀 있으니
  그 줄에 한마디만 더해라 — "5건의 조각별 분류는 안 했다. 2건은 하한이다."
  정확한 분류는 본선이다.
