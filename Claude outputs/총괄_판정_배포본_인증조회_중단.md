## 0. 먼저 — 태그 질문은 오늘 첫 번째가 아니다

태그 시점 (가)/(나)/(다) 를 물었고, 나는 (다)로 기울어 있었다. **그 판정을
보류한다.** 태그를 걸기 전에 재야 할 것이 생겼기 때문이고, 그건 태그보다 비싸다.

그리고 먼저 적을 것 — **이건 내가 놓친 것이다.** 나는 `/healthz` 를 여러 번
불렀고 매번 `sync.recalls` 와 `latest_published_on` 만 읽었다. `kats` 블록을
한 번도 안 봤다. 그 블록은 **바로 이 상황을 보라고 2026-09-11 에 만든 것**이다
(`kats_client.py:127`). 관측은 제대로 돌았고 읽는 쪽이 없었다.

## 2. 원인 — `safetykorea.kr` 의 **이름이 국외에서 안 풀린다**

사이트가 죽은 것이 아니다. 시피님 맥(국내)에서 재 봤다.

    getent hosts www.safetykorea.kr      152.99.46.37        ← 즉시 응답
    curl http://www.safetykorea.kr/...   HTTP 404 · 0.05s    ← 서버는 살아 있다

국외 공개 리졸버로 같은 이름을 물었다.

    리졸버        일반 질의              DNSSEC 검증 끔(+cd)
    8.8.8.8      SERVFAIL              NOERROR  152.99.46.37
    1.1.1.1      NOERROR               SERVFAIL
    9.9.9.9      NOERROR               SERVFAIL

**답이 갈린다.** 우리가 쓰는 다른 호스트는 전부 정상이다.

    www.rra.go.kr                    NOERROR   ← 전파 부적합 동기화가 계속 도는 이유
    openapi.foodsafetykorea.go.kr    NOERROR   ← 식약처. 영향 없다
    www.law.go.kr                    NOERROR
    domeggook.com                    NOERROR

그리고 이 갈림이 배포본의 증상과 **정확히 맞는다.** 같은 시각(2026-09-17
14:21:36Z)에 리콜 동기화는 이름 풀이로 실패했고 전파 부적합 동기화는 성공했다
(`rf_noncompliant_synced_at` 은 `sync.py:121` 에서 **성공했을 때만** 쓴다).

### ⚠ 여기까지가 잰 것이고, 아래는 안 잰 것이다

    잰 것    safetykorea.kr 이름 풀이가 국외 검증 리졸버에서 실패한다

**원인을 DNSSEC 이라고 단정하지 않는다.** 8.8.8.8 은 그 모양이지만 1.1.1.1 ·

## 4. 오늘 순서 — **재는 것이 먼저다. 고르는 것은 그다음이다**

### ① fly 머신 안에서 직접 잰다 (제일 먼저 · 코드 0줄)

세 가지를 본다. **이름이 안 풀리는 것인지, IP 로도 못 나가는 것인지**가
갈래를 정한다.

    fly ssh console -a sourcing-guard -C \
      "python -c \"import socket; print(socket.gethostbyname('www.safetykorea.kr'))\""

    fly ssh console -a sourcing-guard -C \
      "python -c \"import httpx; r=httpx.get('http://152.99.46.37/', headers={'Host':'www.safetykorea.kr'}, timeout=8); print(r.status_code)\""

    fly ssh console -a sourcing-guard -C "cat /etc/resolv.conf"

⚠ 두 번째가 핵심이다. **200/404 가 오면 갈 길이 있고, 붙지도 못하면 없다.**
  (한국 정부 API 는 국외 IP 를 막는 일이 잦다. 우리는 9/1부터 도쿄에서 잘
  불러 왔으니 막혔을 가능성은 낮지만, **잰 적이 없으므로 재고 말한다.**)

### ② 잰 값에 따라 — 셋 중 하나

    (가) 이름만 안 풀리고 IP 로는 나간다
         → Dockerfile 에 `/etc/hosts` 한 줄. **파이썬 코드 0줄.**
           `ensure_allowed(url)` 은 URL 의 호스트명을 보므로 R4 그대로다.
         ⚠ API 가 **http** 다 (`kats_field_map.yaml:83`). 이름을 검증하는
           TLS 가 없으니 IP 가 바뀌면 엉뚱한 서버와 말하게 된다. 그러니
             · IP 옆에 **잰 날짜**를 주석으로 박는다
             · `resultCode` 검사가 이미 막아 주는 범위를 주석에 적는다
             · 미완에 "이 줄은 임시다 · 본선에서 걷는다" 를 적는다

    (나) resolv.conf 가 fly 내부 리졸버고, 1.1.1.1 로는 풀린다
         → 이쪽이 (가)보다 낫다. **우리가 IP 를 박지 않는다.**
         ⚠ 먼저 확인할 것: 우리가 `.internal` 이름을 쓰는 데가 있는가.
           SQLite 라 없을 것 같지만 **확인하고 바꾼다.** 리졸버를 통째로
           덮으면 그것이 같이 죽는다.

    (다) IP 로도 못 나간다
         → 우리가 할 수 있는 것이 없다. ③ 만 한다.

### ③ 화면을 정직하게 — **(다)면 필수, (가)/(나)면 본선**

고쳐도 또 끊길 수 있다. 그래서 이건 원래 있어야 할 것이지만, **오늘 넣을지는
②의 결과가 정한다.**

    · `sync.py` 에 `last_sync_ok_at` 을 **따로** 둔다 — `wrote_something` 일
      때만 쓴다. `last_sync_at`(시도 시각)은 `/healthz` 용으로 그대로 둔다
    · `main.py:676` 이 `last_sync_ok_at` 을 넘긴다
      → 못 받아 왔으면 `_sync_label` 이 빈 문자열을 돌려주고 "…갱신" 절이
        아예 안 붙는다. 앞 절("2026-09-14 공표분까지")만 남는다
    · `index.html:159` 의 "(매일 갱신)" 을 뗀다
    · `watch.html:38` · `watch.html:7` 의 "매일 대조" 도 같은 자리다

⚠ **이건 새 기능이 아니다.** §9 가 막는 "하지 않은 것을 했다고 하는 말" 을
  떼는 것이다. 문구를 쓸 때 참이었고 그 뒤에 거짓이 된 것뿐이다.

⚠ 그리고 **판정을 바꾸지 않는다.** 신호·등급·근거는 손대지 않는다. 바뀌는
  것은 "우리가 언제 받아 왔는가" 한 줄이다. 그래도 **화면 변경이므로**

## 5. 태그 판정

**태그는 오늘의 마지막 행위다. 첫 행위가 아니다.**

네가 물은 "태그 뒤에 커밋하지 않는다" 를 좁게 읽은 것 아니냐 — **아니다.
네 읽기가 맞았다.** 그 문장의 뜻은 두 번째 문장 쪽이다:

    ✓ 태그 해시 == 9/19 배포본의 `GIT_SHA`
    ✗ "태그 뒤에는 한 줄도 못 쓴다"

그리고 네가 잰 Dockerfile/`.dockerignore` 도 확인했다 — `docs/` 는
`.dockerignore` 에 있고 Dockerfile 은 `requirements.txt` · `sourcing_guard/` ·
`scripts/` 만 `COPY` 한다. **파일 내용은 같다.** 다만 **이미지가 같지는
않다** — `ARG GIT_SHA` 가 ENV 로 박히고 `/healthz` 가 그걸 뱉는다. 그래서
문서만 바뀐 커밋이어도 `GIT_SHA` 는 달라진다. 네가 "이미지가 동일하다" 고
쓴 한 줄은 거기서 반 걸음 넘었다. 결론은 안 바뀐다.

**`--compare` 는 본선으로 내린다.** 식약처는 화면에 안 붙어 있고
(`RecallIndex` 는 제품안전정보센터 쪽이다), 그 답이 제출문 어디에도 안 들어가며,
`openapi.foodsafetykorea.go.kr` 은 이번 일과 무관하게 멀쩡하다. 19시를
기다릴 이유가 오늘은 없다.
