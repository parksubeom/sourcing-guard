## 0. 먼저 제 판정 하나를 고칩니다

제가 「급함: 윈도우 PC 에서 `git push origin main`」 이라고 했습니다.

    ✅ push 는 됐습니다.
       GitHub refs/heads/main = cf1012c9756925da1ea2b43a98210cac34b7ad75
       맥 로컬 main = origin/main  (ahead 0 · behind 0)

**그런데 그걸로 문제가 안 풀렸습니다.** 제 판정이 사태를 *작게* 말했습니다.
「아직 안 올라간 커밋이 있다」 가 아니라 **두 줄기가 양쪽으로 갈렸다** 입니다.
그러면 `git push` 는 **거절됩니다.** 제가 그 말을 안 했습니다.

## 3. ⚠⚠ 제 판정 ①을 **지웁니다** — 이미 풀려 있고, 라이브가 더 낫습니다

제가 「`/scan`·`/batch`·`/watch` 의 `h2` 를 `h1` 로 바꾼다」 고 했습니다.
라이브는 **태그를 안 바꾸고 규칙이 둘 다 받게** 했습니다.

    라이브   .intro h1, .intro h2 { ... font-size:60px ... }

**라이브가 맞습니다.** 곁가지 화면(`/guide`·`/samples`·`/misses`·`/unknown`)의
`h1` 은 그 문서의 으뜸 제목이라 **문서 구조상 옳은 태그**입니다. 제 판정은
구조가 아니라 **글자 크기 때문에** 태그를 바꾸라고 한 것이었고, 그건 거꾸로
입니다. 크기는 CSS 의 일입니다.

    ① h1 세 줄        → 삭제. 이미 프로덕션에 있고, 방식도 더 낫다.
    ③ 여백 일부       → `section+section --s12` 도 이미 라이브에 있다.
                        남은 것은 `layout.py` 이관뿐.

## 4. 왜 지금 제일 급한가

    (가) 윈도우 트리가 사라지면 ①·③일부·그림자·칩 통합을 **전부 잃습니다**
    (나) 프로덕션을 **재현할 수 없습니다** — 무슨 코드가 도는지 저장소가 모름
    (다) **아무도 배포를 못 합니다** — ② 도 못 올라갑니다
    (라) 지금 **온라인 투표 중**입니다 (9/21~10/5). 사이트가 내려가면 안 됩니다

(다)가 핵심입니다. 어젯밤 에이전트가 커밋 메시지에 **정확히 이렇게 적어
놨습니다** — 「배포 안 했다. 프로덕션(`4a779b6e9`)이 저장소에 없어 배포하면
어제 밤 작업을 덮는다.」 **에이전트 판단이 맞습니다.** 배포를 멈춘 게 옳습니다.

## 5. 판정 — **0단계를 지금 합니다. 위험 0 입니다.**

### 0단계 · 윈도우 PC 에서 (덮는 것 없음 · 되돌릴 것 없음)

    git fetch origin
    git log --oneline origin/main..HEAD
        ↑ 윈도우에만 있는 커밋 목록. 여기에 4a779b6e9 가 보여야 합니다.

    git branch prod-4a779b6e9 HEAD
    git push origin prod-4a779b6e9
        ↑ **main 이 아니라 새 가지로** 올립니다.

⚠ `main` 에 push 하지 마십시오 — 갈렸으므로 **거절됩니다**.
⚠⚠ `--force` 절대 금지입니다. cf1012c(②)를 지우고, 총괄 규칙 위반입니다.

**이 네 줄이면 잃을 위험이 끝납니다.** 합치기는 그 다음에 천천히 해도 됩니다.

### 1단계 · 합치기

    git switch main
    git merge prod-4a779b6e9

충돌은 `app.css` 한 곳에 몰립니다. **충돌 해결 규칙을 제가 미리 정합니다** —
에이전트가 그 자리에서 고민하지 않게:

    .chip (통합본, align-self 포함)          → **라이브**.  `.lv2 .chip` 삭제
    .lv2-foot → .site-foot (파이썬 포함)      → **라이브**
    .intro h1, .intro h2                     → **라이브**  ← 이게 ① 이다
    section+section{--s12}                   → **라이브**
    body{word-break:keep-all}                → **라이브** (여덟 장)
    --shadow-1:none (다크) + 카드 표면 14개   → **라이브**
    nav.pages a[aria-current] padding 좌우    → **저장소(cf1012c)**  ← ②
    .masthead ...::after{width:124px}        → **저장소(cf1012c)**  ← ②

**거의 전부 라이브를 취하고, ② 두 줄만 저장소에서 가져옵니다.**

### 2단계 · 배포 전에 재는 것 (투표 중이므로 빠뜨리지 않습니다)

    □ 검사 전부 통과 (맥 기준 1,860 + 윈도우 쪽 검사)
    □ 다섯 숫자 무변화   분모 135 · ① 104 · ② 0 · ③ 104 · ④ 0 · ⑤ 3
    □ 여덟 장 내비 좌표 가짓수 **1**
    □ 배포 뒤 `/healthz.build.commit` 이 **origin/main 에 있는 SHA** 로 찍히는가
      → 이게 이번 사고의 재발 방지입니다. 없는 SHA 가 찍히면 그 자리에서 멈춥니다
    □ `/api/v1/showcase` 200 · 29장
    □ `gov_lookup` cert/recall ok
