# 총괄 판정 — **한 번에 한 명만 트리를 만집니다**

## 0. 가장 급한 것 — 검사 결과를 못 믿습니다

에이전트가 찾은 것이 이 판정 전체를 바꿉니다:

> 전체 검사 결과가 회차마다 다릅니다(1854 통과 → 1849 통과 · 실패 1 → 6 → 7).
> 같은 트리를 **두 에이전트가 동시에 읽고 쓰면서** `ast.parse`·
> `inspect.getsource` 가 **반쯤 써진 파일**을 무는 것입니다 — 실패 목록
> 자체를 신뢰할 수 없는 상태입니다.

⚠⚠ **그러면 제가 어제 내린 동결 판정도, 오늘 승인한 P4 배포도 근거가
  흔들립니다.** 제가 "전체 1,855 통과" 를 받아 적고 판정했는데, 그 숫자가
  **무엇을 잰 것인지 모르는 상태**였습니다.

이 저장소가 이미 겪은 모양입니다 — §6 *"배경 작업을 재실행하기 전에 이전
프로세스를 먼저 확인하고 죽인다. … 둘이 동시에 API 를 때려 … **27분 동안
몰랐다**."* 그때는 API 였고 이번엔 파일입니다.

## 1. 순서 — 이 순서로만 갑니다

    ① 리팩터 에이전트    **지금 손을 뗍니다.** 작업은 별도 브랜치로 보존
    ② P4 에이전트        자기 파일만 명시 경로로 커밋 → worktree 배포 → 확인
    ③ 전원 손 뗌         작업 트리를 건드리는 사람이 0 명이 됩니다

    ⑤ 배포본 내용 확인    해시가 아니라 **문구를 열어서**
    ⑥ 동결

⚠ ④ 전의 어떤 검사 숫자도 판정의 근거로 쓰지 않습니다. 제가 오늘 받아
  적은 1,855 도 포함입니다.

## 2. 크롬 리팩터 — **미룹니다. 다만 버리지 않습니다**

에이전트 권고가 맞고 논증도 맞습니다:

> *"이득(중복 제거)은 **내부** 것이고 위험(여덟 화면)은 **바깥** 것입니다."*

그대로입니다. 그리고 검사 7개가 빨강인 채로 투표 첫날에 셀러가 보는 화면
여덟 장의 크롬을 바꾸는 것은, 얻는 것에 비해 잃을 수 있는 것이 큽니다.

**다만 작업을 버리지 않습니다.**

    별도 브랜치에 커밋합니다 — 예: `refactor/layout-2026-09-20`
    main 작업 트리는 비웁니다
    투표 종료(10/5) 뒤에 검사 7개를 초록으로 만들고 머지합니다

⚠ 브랜치를 새로 만드는 것은 히스토리 rewrite 가 아니므로 §6 의 총괄 확인
  대상이 아닙니다. **판단으로 하십시오.**

⚠ 커밋 메시지에 **왜 미뤘는지**를 적으십시오 — "검사 7개 빨강 · 투표 첫날 ·
  화면 여덟 장" 세 가지. 안 적으면 10월에 열어 본 사람이 "왜 안 머지했지"
  부터 다시 조사합니다.

## 3. P2 주석에 검사를 안 붙인 판단 — **맞습니다**

> *"세 자리가 「지금 이 문구」인 것을 검사로 굳히면 §6 이 말하는 「현재 출력을
> 기대값으로 적어 버그를 고정하는」 모양이 됩니다. 오늘 `test_scorer` 에서
> 제가 정확히 그 검사를 걷어냈는데, 같은 걸 새로 심을 수는 없습니다."*

제 지시는 "주석에 적어라" 였고, 에이전트가 **"검사는 붙이지 않는다" 를 스스로
판단하고 근거까지 댔습니다.** 같은 날 자기가 걷어낸 모양을 다시 심지 않은
것이 정확합니다.

## 4. 배포 확인 — **CLAUDE.md 에 넣습니다**

에이전트가 배운 것이 규칙이 될 값입니다:

> *"배포 확인은 `/healthz` 의 빌드 해시가 아니라 **바뀐 문구 자체를 열어
> 봐야** 합니다. 해시는 build-arg 로 넣는 값이라 트리와 어긋날 수 있습니다.
> 오늘 실제로 어긋났습니다."*

⚠⚠ **그리고 이번 건은 확인이 두 겹인데 둘 다 비었습니다.**

    에이전트   `fly deploy` 성공만 보고 내용을 안 열었다
    총괄       에이전트 보고를 열지 않고 받아 적었다

**한 겹이 비면 다른 겹이 잡는 구조였는데, 같은 종류의 생략이라 둘 다
통과했습니다.** 그래서 규칙을 양쪽에 겁니다:

    § 배포는 **바뀐 것을 열어서** 확인한다. 성공 로그도 빌드 해시도
      배포된 것이 아니다. 해시는 build-arg 이고 트리와 어긋날 수 있다
      (2026-09-20 실제로 어긋남 — 커밋 22:45 · 빌드 22:48 · 내용은 옛 것)

    § 총괄은 에이전트 보고의 **화면·응답을 직접 한 번 연다.** 보고를 옮겨
      적은 것을 검증이라 부르지 않는다

**②를 제가 어겼습니다.** 제 몫으로 같이 적어 주십시오.
