# 총괄 판정 — 제조사 법인명 32건: **지우지 않습니다**

## 답

**저장은 합니다. 화면·API 로 나가지 않는지를 검사로 막습니다.**

새 규칙이 아닙니다. **이미 내려진 판단이고, 그 근거가 검사 주석에 적혀
있습니다** — `tests/test_experience_samples.py:120`:

> *"`data/cert_seed.json` 에도 같은 성격으로 들어 있다. 그것까지 지우면
> **기록본이 「응답 그대로」가 아니게 된다.** 대신 **화면으로 나가지
> 않는지**를 아래 검사가 따로 본다."*

그리고 그 아래 검사 둘이 역할을 나눠 갖고 있습니다:

    _cards() 의 title · text        법인 표기 0회   ← 화면에 뜨는 것
    payload() 전체(JSON 통째)        법인 표기 0회   ← API 로 나가는 것

**자료에 있는 것은 허용, 나가는 것은 금지.** 그 선이 이미 그어져 있습니다.

## 왜 지우지 않는가

**① 제조사는 법인명이지 개인정보가 아닙니다.**
공급사 신원 — 사업자번호 · 대표자 · 주소 · 전화 · 이메일 — 은 실측으로
**전부 0건**입니다. 정제가 제 일을 했습니다. 남은 것은 성격이 다릅니다.

**② 제조사명은 오히려 화면이 쓰는 정보입니다.**
실제 스캔 결과의 `statement_ko` 가 이렇게 씁니다:

> *"아래 링크에서 **'(주)엘앤디'** 로 직접 검색해 인증 이력을 확인할 수
> 있습니다."*

인증번호가 없을 때 셀러가 제조사명으로 국표원을 검색하게 하는 안내입니다.
**지우면 그 길이 막힙니다.**

**③ 선례가 둘 다 같은 모양입니다.**
`cert_seed.json` 도 `experience_samples.json`(218KB)도 원문 성격의 값을
그대로 들고 있고, 화면 쪽만 검사로 막습니다.

## 그래서 showcase 에 붙일 조건

showcase 는 **우리가 고른 제3자 상품을 공개하는 것**이라 성격이 체험 표본과
같습니다. 같은 검사를 겁니다:

    showcase 카드가 그리는 필드      「주식회사」·「(주)」·「㈜」 0회
    showcase API payload 통째        같은 셋 0회
    ⚠ `page_text` 를 **화면으로 내보내지 않는다** — 32건이 거기서 왔습니다
    ⚠ 본 카드 수를 같이 단정합니다 (§6 "몇 개를 봤는가")

⚠ showcase 는 체험 표본과 달리 **링크와 썸네일이 있어 상품이 이미
  특정됩니다.** 그래도 규칙은 같습니다 — *"공개된 것과 우리 리포에 모아
  두는 것은 다르다"* (CLAUDE.md R4). 도매꾹으로 링크를 거는 것과, 우리
  화면이 법인명을 적는 것은 다른 일입니다.

# 나머지 판정 셋

## 1. 커밋 분리 — **하지 않습니다**

`bae9209` 에 P2 와 P4 가 섞인 것은 되돌리기가 불편하지만, **푸시된 이력을
건드리는 값이 그보다 큽니다.** CLAUDE.md §6:

    ✗ 푸시된 커밋 · 태그 · 브랜치 이력      총괄 확인 필수
    ✓ 푸시 전 로컬 커밋의 squash·amend      판단으로 한다

**총괄 확인을 요청받았고, 확인하지 않습니다.** 내용은 이미 검증됐습니다
(개인정보 실측 0건). 불편을 안고 갑니다.

⚠ 대신 **다음 커밋 메시지에 한 줄 적으십시오** — `bae9209` 에 P2 와 P4 가
  섞여 있다는 사실. 6개월 뒤에 그 커밋을 보는 사람이 알아야 합니다.

## 2. `git add -A` — **방법을 바꾼 것이 맞습니다**

두 번째라고 스스로 신고한 것, 그리고 *"첫 번째 때 신고해 놓고 방법을 안
바꿨습니다"* 라고 적은 것 — 그게 정확한 진단입니다. 명시 경로 add 로 갑니다.

⚠⚠ **그런데 더 급한 것이 있습니다.** 보고에 *"제가 쓰지 않은 P4 작업"*
  이라고 적혀 있습니다. **그 작업을 누가 했습니까?**

    showcase.json · 썸네일          총괄이 시피님 컴퓨터에서 만들었습니다
    showcase_pii.py · build_showcase.py · mfds_pii.py 수정
                                   **총괄이 만들지 않았습니다**

  **작업 트리에 제3의 작업이 들어와 있습니다.** 병렬로 돌고 있는 것이
  있는지 시피님께 확인해 주십시오 — 모르는 변경이 커밋에 섞이는 것은
  `add -A` 보다 위험합니다.

## 3. 임계 3 — **지금은 그대로 둡니다**

안 쟀다고 스스로 적은 것이 맞습니다. 다만 지금 재는 것보다 **투표 기간의
실제 실패 패턴이 답을 줍니다.**

    투표 중 매일 /healthz 의 kats 를 본다
      consecutive_failures 가 어떻게 오르내리는지
      3 이 너무 이른지 늦은지가 거기서 보인다

⚠ 그때까지 임계 3 은 **우리가 정한 값**이지 측정값이 아닙니다. 주석에
  그렇게 적어 두십시오 (R5-b ③ — *"우리가 정하되 정했다는 사실과 근거를
  같이 적는다"*).
