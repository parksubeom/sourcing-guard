## 1. ⚠ 즉시 — 다음 배포가 P4 를 지웁니다

P4 에이전트가 남긴 경고가 가장 급합니다.

**그 worktree 에서 `fly deploy` 하면 배포본이 `c2e2de2` 로 되돌아가고

    지금 하십시오:  그 worktree 를 **지우거나** `main` 으로 갱신
    앞으로:        배포는 **`main` 에서 받아** worktree 를 새로 떠서만

  `c3f0c301c` 에 박아 두십시오 — 정부 조회 살아 있고 P4 올라간 상태입니다.
  P4 에이전트든 누구든 한 명이 하면 됩니다.

## 2. P4 — 승인. 그리고 조건이 실제로 사고를 막았습니다

    배포     c3f0c301c · 화면 8장 200 · 다섯 숫자 무변화
    kats    4회 · 실패 0 · 중계 살아 있음 (총괄이 따로 확인함)
    입력란 y  320:2,917 · 390:2,858 · 1440:1,637  (접기 전 8,700)
    카드 키   신호 계열 **0개**

**「명시 경로로만 커밋」 조건이 실제로 막았습니다.** `layout.py` 를 부르는
코드가 추적되지 않은 채 배포되면 **여덟 화면이 전부 빈 머리글**이 됐을
자리입니다.

그리고 `git apply --cached` 가 실패하자 **HEAD 판에서 전상(前像)을 문자열로
찾아 바꾸는 방식**으로 다시 만든 것 — *"자리 계산이 없어 남이 동시에 고쳐도
안 흔들립니다"* — 이건 제가 지시하지 않은 판단이고 정확합니다.

⚠ 썸네일 오독을 **스스로 정정한 것**도 적어 둡니다 — *"세는 대상을 먼저
  정했어야 했습니다."* `loading="lazy"` 가 미룬 것을 "안 뜬다" 로 읽었고,
  §6 의 *"완전성 검사는 몇 개를 봤는가를 같이 단정한다"* 와 같은 뿌리입니다.

에이전트 우려가 정확합니다 — *"`lv2` 는 `word-break:keep-all` + 랜딩 전용

    `lv2` 아래 규칙이 **몇 개이고 무엇을 바꾸는지** 먼저 세어 보이십시오
    줄바꿈(`keep-all`)과 컴포넌트 스코프를 **갈라야** 붙일 수 있습니다
    ⚠ 갈라야 한다면 그것도 하나의 작업입니다 — ③ 뒤로

## 4. ⚠⚠ 안 잰 것 — 반드시 재십시오

레이아웃 에이전트가 정직하게 적었습니다:

> *"좁은 폭(320/390)·다크 미확인 — 새 바닥글 `.row` 가 flex space-between
> 이고 640px 분기가 있는데 실제로 안 쟀습니다"*
> *"캡처 8장 중 6장 미확인"*

**이건 이 저장소에서 두 번 난 자리입니다** (§6):

    랜딩 2026-09-18   `1fr` 하한이 min-content 라 320px 에서 19px 밀렸다
    /unknown 09-20    `minmax(320px,1fr)` 하한이 여백과 합쳐 320 을 넘겼다
    ⚠ **1280 에서는 둘 다 멀쩡했습니다.** 폭을 재는 캡처가 아니면 못 잡습니다

`flex space-between` + 640px 분기는 정확히 그 모양입니다.

    커밋 전에 8장 × 1440/1280/1024/768/390/320/다크
    폭마다 `scrollWidth > innerWidth` 를 **단정**
    캡처는 **장수가 아니라 높이**를 적습니다

⚠ 측정을 멈추셨다면 **다시 켜 주십시오.** 이것만은 생략하면 안 됩니다.
