## 1. 관세청 세관장확인대상물품 (data.go.kr/data/15101589)

### 확정한 것

| | |
|---|---|
| API 유형 | REST |
| 심의유형 | **개발단계 자동승인 / 운영단계 자동승인** — 대기 없음 |
| 트래픽 | 개발계정 10,000/일. 운영계정은 활용사례 등록 시 증액 |
| 비용 | 무료, 이용허락범위 제한 없음 |
| 인증 | data.go.kr `serviceKey`. **UNI-PASS 별도 가입 불필요** |

```
GET https://unipass.customs.go.kr/gxt/rest/tradeStats/getRetrieveCcctLworCd
    ?serviceKey={키}&hsSgn={HS 10자리}&imexTpcd={1 수출 / 2 수입}
```

호스트가 `unipass.customs.go.kr` 이라 UNI-PASS 자체 키(`crkyCn`)를 쓰는 다른
관세청 API 와 혼동하기 쉽다. 실측: 키 없이 호출하면 HTTP 200 에 
`<resultCode>02</resultCode><resultMsg>인증키가 존재하지 않습니다.</resultMsg>`.
`crkyCn=TEST` 를 넣어도 같은 메시지 — 인증 파라미터는 `serviceKey` 다.

응답 필드 8개 (기술문서 원문):

| 필드 | 뜻 |
|---|---|
| `hsSgn` | HS 부호 |
| `dcerCfrmLworCd` / `dcerCfrmLworNm` | 신고인 확인법령 코드 / 법령명 |
| `reqApreIttCd` / `reqApreIttNm` | 요건승인기관 코드 / 기관명 |
| `reqCfrmIstmNm` | **요건확인서류명** — 포털 요약에 없는 필드 |
| `aplyStrtDt` | 적용시작일자 |
| `bfhnAffcRtmTpcd` | 사전/사후/실시간 구분코드 |

기술문서 예제 응답: HS `3307903000` → `약사법` / `한국의약품수출입협회` /
`표준통관예정보고서(의약품등)`.

### 우리 세 축이 확인법령에 있는가 — 있다 (키 없이 확인)

법령 API 로 「관세법 제226조에 따른 세관장확인물품 및 확인방법 지정고시」
(2026-07-16, 관세청)를 받아 **[별표 2] 세관장확인대상 수입물품** 을 열었다.
키가 필요 없는 경로다:

```
1) https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=admrul&type=XML&query=세관장확인
   -> 행정규칙일련번호 2100000282502
2) https://www.law.go.kr/DRF/lawService.do?OC=test&target=admrul&type=XML&ID=2100000282502
   -> 본문에서 flDownload.do?flSeq=... 22개 첨부
3) https://www.law.go.kr/LSW/flDownload.do?flSeq=168916361   ([별표 2], HWPX=ZIP)
```

별표 2 의 법령 37개에 다음이 들어 있다:

- **「어린이제품 안전 특별법」**
- **「전기용품 및 생활용품 안전 관리법」** — 고시 표기에 **'안전 관리법' 띄어쓰기**가
  들어간다. 문자열 매칭 시 주의
- **「전파법」**
- 「화장품법」·「약사법」·「수입식품안전관리 특별법」·「위생용품 관리법」·「의료기기법」

고시 부칙 원문도 같은 얘기를 한다 — *"「어린이제품안전특별법」에 근거하여
신규지정되는 대상물품은 2018년 11월 1일 수입신고분부터 적용"*,
*"「전기용품 및 생활용품 안전관리법」 대상물품 중 자동차용 타이어는 2022년
7월 1일부터 시행"*.

### 붙이지 않는 이유

요청 파라미터가 `hsSgn`·`imexTpcd` 뿐이다. **품목명 조회 경로가 없다.** 셀러가
넣는 "블루투스 이어폰" 을 HS 10자리로 바꾸는 단계가 앞에 붙고, 그 추정에는
검증할 정답지가 없다.

HS 사전 후보 (둘 다 **파일 데이터셋** — 키 불필요할 가능성):
- `관세청_HS부호 단위별 품목명` /data/15130660 (XLSX, 2026-01-19 갱신)
- `관세청_표준품명` /data/15049721 (XLSX, 2026-01-02 갱신)

**미확인**: 위 파일 다운로드에 data.go.kr 로그인이 필요한지 (페이지가 JS 구동이라
URL 을 추측하지 않았다). HS 단위 매핑 자체도 같은 고시의 **[별표 2의2] HSK 10단위로
연계되는 물품의 수입요건** 에 있는데, HWPX 는 자리표시자이고 실제 표는
`개정전문(별표 2의2…)_260716.xlsx` 첨부다 — 그 다운로드 URL 은 못 찾았다.

**미확인**: HS 별 실제 응답. 키가 없어 `dcerCfrmLworNm` 에 전안법·어린이제품법이
실제로 담겨 오는지는 못 찍었다. 별표 2 로 "대상 법령이다" 까지만 확정했다.

## 2. safetykorea 품목 트리 — 왜 보류인가 (오독 주의)

### 확정한 것

```
POST (또는 GET) https://www.safetykorea.kr/release/ajax/itemSearch
Accept: application/json          <- 이게 없으면 HTTP 500
body: itemSearch=1..9
```

인증키·세션쿠키·JS 챌린지 **전부 불필요**. `Accept: */*` 로 부르면 500 이 나는데
Spring content-negotiation 문제이고 우리 잘못이다.

응답: `{"success":true,"total":179,...,"list":[{"totalCode":1010101,
"fullName":"전선 및 전원코드>전선, 케이블 및 코드류>절연전선(공칭단면적 95㎟이하)"}]}`

`totalCode` 7자리, **첫 자리가 제도**다:

| 첫 자리 | 제도 | 건수 |
|---|---|---|
| 1 / 2 / 3 | 전기용품 안전인증 / 안전확인 / 공급자적합성확인 | 179 / 259 / 183 |
| 4 / 5 / 6 | 생활용품 안전인증 / 안전확인 / 공급자적합성확인 | 14 / 61 / 21 |
| 7 / 8 / 9 | 어린이제품 안전인증 / 안전확인 / 공급자적합성확인 | 4 / 17 / 15 |

**합계 753건. 9회 호출 1.3초** (개별 최대 0.22초). 페이징 없음. RRA(12초)와 달리
버튼으로 뺄 필요가 없고 스냅샷으로 커밋해도 되는 크기다.

`fullName` 형식이 우리가 이미 쓰는 `certificationList` 응답의 `categoryName` 과
같아서(둘 다 `대분류>중분류>소분류`) 기존 인증 조회 결과와 조인된다.

### ⚠ 보류 이유를 "어휘 격차" 로 적으면 안 된다

그렇게 남기면 다음 사람이 **"매핑 테이블을 만들면 풀린다"** 고 착각한다. 실제
이유는 두 개이고 둘 다 매핑으로 안 풀린다.

**(1) 질의 파라미터가 애초에 없다.**

`ajax/itemSearch` 는 `itemSearch=1..9` 만 받는다. 키워드를 붙여도 무시된다 (실측):

| 요청 | total |
|---|---|
| `itemSearch=8` | 17 |
| `itemSearch=8&prdtNm=완구` | **17** — `prdtNm` 이 무시됐다 |
| `itemSearch=완구` / `prdtNm=완구` / `keyword=완구` | 0 |

즉 "질의어를 고친다" 는 선택지가 존재하지 않는다. 이 화면은 키워드 검색이 아니라
**카테고리 드릴다운**이고, 매칭은 전량 우리 쪽 로컬에서 일어난다.
(키워드 검색은 별도 `POST /release/certificationsearch` 에 `certNum`·`productName`·
`modelName`·`makerName`·`importerName` 으로 있지만, 그건 **품목이 아니라 인증
레코드**를 찾는다. `productName` 만 보내면 HTTP 500 — 카테고리 코드가 함께 필요하다.)

**(2) 로컬 매핑을 만들어도 새로 얻는 것이 없다.**

우리 `ItemCategory` 7개 버킷과 트리의 대응:

| ItemCategory | 대응 leaf | 트리가 주는 등급 | 새로 얻는 것 |
|---|---|---|---|
| `children_toy` | `완구` (8010600) | 어린이·안전확인 | **없음** — 규칙 DB 로 이미 안다 |
| `children_stationery` | `학용품` (8011100) | 어린이·안전확인 | **없음** |
| `children_textile` | `유아용 섬유제품`(8010100) / `아동용 섬유제품`(9011500) | 안전확인 / SCoC | 두 leaf 로 갈려 버킷 하나로 못 고른다 |
| `electrical` | 621건 중 하나 | 인증·확인·SCoC 전부 있음 | **우리가 원한 것. 그런데 621건 중 어느 것인지 고를 수 없다** |
| `household` | 96건 중 하나 | 동일 | 동일 |
| `out_of_scope` · `unclassified` | — | — | — |

손으로 쓸 수 있는 고정 매핑은 **어린이제품 3줄뿐이고 그건 이미 아는 것**이다.
우리가 원한 전기용품·생활용품은 **버킷 하나 대 717건**이라 고정 테이블로 내려갈 수
없다.

**정확히 하자.** 트리에 전기용품 등급이 **없는 게 아니다** — 621건 전부 등급을
달고 있다. 못 쓰는 이유는 데이터가 없어서가 아니라 **주어진 상품에 대해 어느
leaf 인지 고를 수 없어서**다. leaf 선택은 수백~수천 후보 중 하나를 고르는 분류
문제이고 검증할 정답지가 없다 — HS코드와 같은 성질의 문제다.

참고로 어휘 격차는 실재하지만 그건 위 (2)의 증상일 뿐이다 (실측: 골든셋 11건
전부 leaf 와 0건 일치. `이어폰`→트리엔 `무선 헤드셋`, `슬라임`→`완구` 하나,
`보조배터리`→`단전지` 계열, `휴지통`·`가방`→아예 없음). 또 leaf 의 **23.9%(180건)
가 "기타" 또는 빈 이름**이라 이름만으로는 판별 자체가 안 된다.

### 붙일 때 반드시 함께 할 것 — 안전기준준수 24품목

트리는 **안전인증·안전확인·공급자적합성확인 3계층뿐**이고 **안전기준준수 대상
생활용품은 들어 있지 않다.** `/policy/targetsSafetyStandard` 가 그 목록이다.

트리 753건 대조 실측:

| 품목 | 트리 |
|---|---|
| 텐트 · 양탄자 · 벽지 · 수세미 · 침대매트리스 · 가정용 섬유제품 | **0건** |
| 가죽제품 | `어린이용 가죽제품` 뿐 |
| 선글라스 · 안경테 | `어린이용 안경테` 뿐 |
| 우산 · 양산 | `어린이용 우산 및 양산` 뿐 |

성인용 가죽가방·선글라스·텐트·매트리스는 대량 소싱 품목인데 트리에 없다. 트리만
믿고 "대상 아님" 을 판정하면 **이것들이 조용히 GREEN 으로 빠진다** — R3 위반이다.

### 미확인

- `itemSearch=3` 이 "전기용품 공급자적합성확인" 이라는 라벨은 **사이트 어디에도
  명시가 없다.** 전기용품 SCoC 품목표 페이지가 존재하지 않는다
  (`/policy/targetsSafetyProvider` 는 표 0개). 6·9 는 정책 페이지 목록과 정확히
  일치해 확정됐지만 3 은 정황 추론이다. 전기용품이 트리의 82.5% 라 이 라벨이
  틀리면 등급 표시가 통째로 어긋난다 — **채택 전 사람 검수 필수.**

### SafetyKorea Open API 에는 품목 오퍼레이션이 없다

명세서 v2.0 의 엔드포인트는 5개가 전부다 — `cert/certificationList`,
`cert/certificationDetail`, `recall/recallList`, `recall/recallDetail`,
`recall/fRecallList`. 우리 `kats_field_map.yaml` 이 담고 있는 것과 일치한다.
**품목 목록을 주는 오퍼레이션을 쓰는 코드가 나오면 환각이다** — CLAUDE.md §4 의
유해물질 기준 API 와 같은 함정.

`certificationList` 응답의 `certDiv`(예: `어린이제품 특별법 대상>안전확인 대상`)와
`categoryName` 은 인증번호→품목→제도를 잇는 조인 키로 쓸 수 있다. 단 `certDiv` 는
안전인증·안전확인만 표현하고 SCoC 는 표현하지 않는다.

## 3. 식약처 · 소비자24

### A. 식품 회수·판매중지 (data.go.kr/data/15074318)

- data.go.kr 등록은 **LINK**. 실제 키는 **식품안전나라에서 별도 발급, 자동승인**
  (원문: *"※ 인증키는 신청후 자동으로 승인되어 발급이 완료됩니다."*)
- 서비스ID `I0490`, 요청주소 `http://openapi.foodsafetykorea.go.kr/api/{키}/{서비스}/{타입}/{시작}/{종료}`
- 선택 요청인자 3개뿐: `CRET_DTM`(등록일자) · `PRDLST_REPORT_NO`(품목제조보고번호) ·
  `CHNG_DT`(변경일자). **제품명(`PRDTNM`)은 출력 전용** — 서버측 제품명 검색 불가
- API 호출제한 2000/일
- 무키 샘플키(`/api/sample/I0490/...`)는 `ERROR-503 09시~19시에는 서비스가 일시적으로
  원활하지 않을수있습니다` 를 돌려준다. 20초 간격 6회 재시도 전부 동일 →
  일시 장애가 아니라 **09–19시 KST 상시 차단**. 낮에는 응답 확인 자체가 안 된다
- 붙인다면 전량 pull → 로컬 색인. 리콜 사본과 같은 구조다

### B. 화장품 규제정보 (data.go.kr/data/15111773) — 붙일 값이 없다

- REST, 개발 자동승인 / 운영 심의승인, 개발계정 10,000
- `apis.data.go.kr/1471000/CsmtcsReglMaterialInfoService/getCsmtcsReglMaterialInfoService`
- **요청 파라미터 4개가 전부**: `serviceKey`·`pageNo`·`numOfRows`·`type`.
  **검색 파라미터가 하나도 없다** — 성분명으로도 못 찾는다
- 응답 item 5필드: `SN`·`INGR_STD_NAME`·`INGR_ENG_NAME`·`PROH_NATIONAL`·`LIMIT_NATIONAL`
- 무키 → HTTP 401 `SERVICE_KEY_IS_NULL` / 더미키 → HTTP 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`
- **방향이 반대다.** 포털 설명 원문이 *"글로벌 시장 진출을 위한 전략 수립"* 이다 —
  `PROH_NATIONAL` 은 "어느 **외국**이 이 성분을 금지하는가" 로, 수출용 정보다.
  우리 셀러는 수입·국내판매라 "한국에서 써도 되는가" 가 필요하다
- 게다가 제품이 아닌 **성분 단위**라, 붙이려면 상세페이지 전성분 추출이 앞에 붙는다
- **미확인**: `PROH_NATIONAL`/`LIMIT_NATIONAL` 의 실제 값 모양(한글 국가명인지 ISO
  코드인지, 단일값인지 구분자 목록인지). Swagger `example` 이 전부 비어 있고
  파일데이터 버전도 없다

### 화장품은 이걸 쓸 것 — 회수·판매중지 (data.go.kr/data/15106958)

- REST, **개발 자동승인** / 운영 심의승인, 개발계정 10,000
- `apis.data.go.kr/1471000/CsmtcsRtrvlSleStpgeInfo/getCsmtcsRtrvlSleStpgeInfo`
- **요청 파라미터에 `ITEM_NAME`(품목명)·`ENTP_NAME`(업체명)·`DISPS_CONT`(회수사유)가
  있다** — 식약처 API 중 유일하게 제품명 서버측 검색이 된다
- 응답: `ITEM_NAME`·`ENTP_NAME`·`ADDR`·`DISPS_CONT`·`MAKE_NO`·`MAKE_DATE`·
  `VALID_DATE`·`APPROVAL_DATE`·`RECALL_COMMAND_DATE`·`OPEN_END_DATE`·`ETC`
- 무키 → HTTP 401 `SERVICE_KEY_IS_NULL` (엔드포인트 실존 확인)
- **화장품을 붙일 때는 B(15111773) 가 아니라 이것이다.**

### C. 소비자24 (consumer.go.kr) — 보완이지 대체가 아니다

- 26개 기관 1,000만 건 통합. 운영주체 **공정거래위원회** (옛 행복드림, 2021 개편)
- 참여기관에 국가기술표준원(KC인증정보·안전관리정보), 식약처 등 34행
- 실측 건수: 공산품 리콜 4,470 (출처 국표원) / 식품 389 / 화장품 29 (출처 식약처) /
  KC인증 **1,057,461건**
- **키가 병목이다.** data.go.kr 에 공정위 명의 리콜 API 9건이 "자동승인" 으로
  올라와 있지만 **전부 LINK** 라 목적지가 `consumer.go.kr` 이고, 활용신청 시
  *"본인확인이 필요한 서비스입니다"* 모달이 뜬다. data.go.kr 서비스키로는 호출 불가
- 엔드포인트 실측 (**오류도 HTTP 200 으로 온다 — body 의 `code` 를 봐야 한다**):
  - `/openapi/recall/contents/index.do?pageNo=1&cntPerPage=10&cntntsId=0101`
    → 200 `<code>40</code> 잘못된 요청 파라메터 에러`
  - 더미키 → 200 `<code>50</code> 등록되지 않은 서비스키 에러`
  - 코드: `00` 정상 / `30` NODATA / `40` 파라미터 / `50` 미등록키
- 리콜 API 선택 변수에 **`productNm`(제품명)·`modlNmInfo`(모델명)·
  `recallProcssInfo`(인증번호)** 가 있고, 인증 API(`/openapi/crtfcs/03`)에
  **`productNm`·`modlNm`·`crtfcNo`·`crtfcSttus`** 가 있다 → **제품명 서버측 검색이
  되는 유일한 경로**
- `crtfcSttus` 실제 값에 **안전인증취소 / 안전확인신고 효력상실 / 안전인증표시
  사용금지 2개월 / 취소 / 정지 / 청문실시** 가 그대로 있다 → R3-b 가 요구하는
  "정부 DB 가 적극적으로 문제를 적어둔 사실" 에 정확히 대응
- 다만 상세 화면이 스스로 *"제공기관과 내용이 다른 경우에는 제공기관의 정보가
  우선합니다. 제공기관: 국가기술표준원"* 이라고 못박는다. **원본은 여전히
  SafetyKorea** — 대체가 아니라 보완이다
- 유해물질 기준치는 소비자24 에도 **없다**. CLAUDE.md §4 의 전제는 유지된다
- **미확인**: 승인 소요 시간, 일일 호출 한도(가이드 PDF 3종에 기재 없음),
  선택 파라미터의 부분일치 여부(문서 기준일 뿐 런타임 미검증), 소비자24 식품·화장품
  리콜 건수(389/29)가 식약처 원본의 전량인지 부분집합인지
