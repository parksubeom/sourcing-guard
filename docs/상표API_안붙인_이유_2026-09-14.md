# 상표 API 를 왜 안 붙였나 — 2026-09-14

본선에서 받을 질문이라 답을 미리 적어 둔다.

## 한 줄

**데이터가 없어서가 아니다.** 우리가 **판정하지 않기로 한 것**이라, API 가 있어도
화면 문구가 같기 때문이다.

## 긴 답

지재권은 이 도구의 축이 아니다. 우리가 하는 일은 셋이다 — KC 인증번호가 실재하는가,
리콜 공표 목록과 대조되는가, 어떤 유해물질 기준이 걸리는가. 셋 다 **정부 DB 가 답을
갖고 있고 우리는 조회만 한다**(R1).

상표는 그 모양이 아니다. "이 상품명이 누군가의 등록상표와 같은가" 를 알아도
**침해인지는 전혀 다른 판단**이다 — 지정상품이 겹치는가, 식별력이 있는가, 선사용권이
있는가, 사용 태양이 상표적 사용인가. 그 판단은 권리자와 특허심판원·법원이 한다.
우리가 "등록상표와 같습니다" 를 신호로 바꾸면 그 순간 §9 가 금지하는 단정이 된다.

그래서 화면이 할 수 있는 최선은 이것이다:

> '호환' 표기가 있습니다. 상표·디자인권은 이 도구가 확인하지 않습니다 —
> 권리자·KIPRIS 확인 필요

**이 문장은 API 를 붙여도 바뀌지 않는다.** 조회 결과가 "등록상표 3건" 이어도 우리가
덧붙일 수 있는 말이 없고, "0건" 이어도 "안전하다" 고 말할 수 없다(미등록 상표·
디자인권·부정경쟁이 남는다). 축이 줄을 가르지 못한다.

## 데이터 쪽 사정도 함께 적는다

시피님이 KIPRIS Plus 목록을 '상표' 로 검색해 여섯 건을 확인했다 — 출원 속보 ·
행정처리 이력 · 분류코드 변동 이력 · 법적 상태 이력(ST.27/ST.87) · 상표 원산지 명칭 ·
해외상표. **전부 대량 데이터 내려받기이고, 낱말을 던져 답을 받는 검색 서비스가 없다.**

즉 붙일 API 자체가 없다. 그래서 적중률 측정도 하지 않았다 — 잴 대상이 없는데 수를
만들면 그 수가 나중에 근거로 쓰인다.

## 대신 한 것

`data/ip_markers.yaml` 에 **실측으로 걸린 표기어 둘**을 두고 안내 한 줄과 링크를 준다.

    호환   19,173줄에서 45건   (도매꾹 44 · 새표본 1)
    st     한글 바로 뒤만 4건  (띄어 쓴 ST 는 3/4 가 모델 번호라 뺐다)

후보 13개 중 열하나는 표본에서 0건이거나 전부 오탐이라 넣지 않았다(크레파스 원칙 ·
버린 이유는 yaml 주석에 건수와 예까지 적혀 있다).

링크는 둘이다. **둘 다 2026-09-14 에 본문 `<title>` 로 확인했다** — law.go.kr 은 없는
주소에도 200 을 준다.

    상표법     https://www.law.go.kr/법령/상표법
    KIPRIS     https://www.kipris.or.kr/khome/search/searchResult.do?tab=trademark

⚠ **검색어를 주소에 담지 않는다.** KIPRIS 검색 폼은 POST 라 주소로 미리 채울 수 없다.
브라우저에서 셋을 재 봤다:

    ?queryTextTop=완구                 뒤쪽 검색칸은 채워지는데 탭이 특허이고
                                       결과가 안 돈다(검색 팁 화면만 뜬다)
    ?tab=trademark&queryTextTop=완구    상표 상세검색 창이 뜨는데 그 창의
                                       자유검색 칸은 **비어 있다**
    ?tab=trademark                     상표 검색 창이 바르게 뜬다   ← 이것을 쓴다

반쯤 채워진 주소를 쓰면 셀러가 "검색된 줄" 알고 빈 화면을 읽는다. 대신 화면에
**상품명 복사** 버튼을 두어 붙여넣게 한다.
