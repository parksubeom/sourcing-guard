## 4. git 밖에 있는 것

### `.env` — 커밋 안 됨. 집에서 다시 만들어야 한다

`.env.example` 을 복사해 채운다. 오늘 기준 설정 상태:

| 키 | 상태 | 비고 |
|---|---|---|
| `MOCK_MODE` | 값 있음 | true 면 외부 호출 없이 픽스처로 구동 |
| `ANTHROPIC_API_KEY` | 값 있음 | 없으면 휴리스틱 추출로 대체 구동된다 |
| `EXTRACTOR_MODEL` | 값 있음 | |
| `KATS_BASE_URL` | **비어 있음** | 의도다. 시험용 오버라이드일 때만 채운다 |
| `KATS_SERVICE_KEY` | 값 있음 | ⚠ 서비스 ID 가 등록 IP 에 묶인다. 집 IP 에서 부르면 4001 이다 |
| `WATCHLIST_DB_PATH` | 값 있음 | |
| `SYNC_ENABLED` | 값 있음 | |
| `SYNC_TOKEN` | 값 있음 | 비우면 `POST /api/v1/sync` 가 403 |

⚠ **`KATS_SERVICE_KEY` 는 IP 에 묶인다.** 집에서 실연동이 4001 로 떨어지면
키가 틀린 것이 아니라 IP 미등록이다. `MOCK_MODE=true` 로 돌리면 전
파이프라인이 픽스처로 돈다.

### 로컬 DB — 커밋 안 됨 (33MB + WAL 34MB)

```
data/watchlist.db        33MB   리콜 로컬 사본 + 감시 목록
data/watchlist.db-wal    34MB
```

집에서는 비어 있는 상태로 시작한다. 리콜 대조가 필요하면
`POST /api/v1/sync` 를 `SYNC_TOKEN` 헤더로 부르거나, `SYNC_ENABLED=true` 로
서버를 띄우면 시작 시 1회 적재한다(전건 약 4만 건, 처음 적재는 몇 분).

리콜 사본이 없으면 `LOOKUP_FAILED` 가 붙고 신호가 UNKNOWN 이 된다 —
대조하지 않은 것을 대조했다고 말하지 않기 위한 설계이니 정상이다.

## 5. 집에서 시작하는 순서

```bash
git clone <repo> && cd sourcing-guard
python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env      # MOCK_MODE=true 로 두면 키 없이 전부 돈다
.venv/bin/python -m pytest -q --deselect tests/test_ratelimit.py
.venv/bin/python -m uvicorn sourcing_guard.main:app --reload
```

측정을 다시 돌려 상태를 확인한다.

```bash
PYTHONPATH=. .venv/bin/python scripts/measure_hint_effect.py
PYTHONPATH=. .venv/bin/python scripts/match_review.py tests/fixtures/도매꾹239.txt
PYTHONPATH=. .venv/bin/python scripts/classify_misses.py tests/fixtures/도매꾹239.txt
```

⚠ `tests/test_ratelimit.py` 는 19건이 5분 이상 걸린다. 개발 중에는
`--deselect` 하고, 커밋 전에 한 번 전체를 돌린다.
