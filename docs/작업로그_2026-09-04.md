## 1. 매처 — 매칭이 두 단계라는 것을 코드로 드러냈다

부속어 가드가 원시적인 매처였는데 여섯 곳에 흩어져 있었다. 한곳에 모았다.

```
1단계  검색   표의 이름이 상품명 안에 있는가        → 후보 목록  (재현율)
2단계  매처   각 후보가 정말 이 상품을 가리키는가   → 참·거짓 + 신뢰도  (정밀도)
```

2단계가 없어서 "안전모 햇빛가리개" 가 안전모로, "고데기 거치대" 가
전기머리인두로 붙었다.

### 신호 넷

| 신호 | 무엇을 본다 |
|---|---|
| `accessory_or_negated` | 키 뒤에 부속어·부정어가 붙는가 ("고데기 거치대", "고데기없이") |
| `chemical_variant` | 접미 한 글자가 화학제인가 ('제습제' vs '제습기') |
| `chemical_rival` | 같은 일을 하는 화학제인가 (핫팩 vs 전기손난로) |
| `consumable` | 소모품 표기가 있는가. **단독으로는 거부하지 않는다** |

### ⚠ 매처는 거부하는 쪽으로만 강하다

참을 만들어내지 않는다. 근거 없이 매칭을 늘리면 등급이 뒤집히고, 그것이
셀러를 위법 상태로 보낸다. 이 원칙이 `judge()` 의 설계이고, 신호를 더할
때도 지켜야 한다.

### 매처는 신호를 **계산하지 않고 받는다**

호출측(`ItemGradeBook`)이 이미 정규화를 했으므로 규칙을 두 곳에 두지 않는다.
`judge(names_subject=..., chemical_dominates=...)` 형태다.

⚠ 그래서 **`scripts/measure_matcher.py` 가 `judge()` 서명을 따라간다.**
신호를 더하면 스크립트도 같이 고쳐야 하고, 안 고치면 새 신호가 0으로 보인다.
오늘 두 번 겪었다 (`chemical_rival` · 경쟁 단계).

### 실측 (도매꾹 239건)

```
1단계가 찾아온 후보   288개
  매처가 통과시킴      271개   likely 106 · possible 165 · certain 0
  매처가 거부함         17개
    accessory_or_negated 12 · chemical_variant 3 · chemical_rival 2
```

**`certain` 이 0개인 것이 이 표본의 성격이다.** 도매 상품명 중 표의
품목명과 그대로 같은 것이 하나도 없다 — 전부 브랜드·수식어·연관 검색어가
붙는다. 별칭 24개를 넣어야 했던 이유가 숫자로 나왔다.

## 2. 경쟁 품목 — 닫는 대신 양보하게

`의자` 를 `_WEAK_CONTAIN_KEYS` 에 넣어 닫아 뒀는데, 그러면 **방석도 의자도
답을 못 준다.** 실측에서 의자 계열 8건이 전부 미매칭이었다.

방석은 비대상이 아니라 **표에 있는 다른 품목**이다 — 부속서 1 기타 제품류가
"쿠션류, 방석류" 를 명시하고, 표에 `의류 이외의 섬유제품`(안전기준준수)이
있다. 양쪽 다 답이 있는데 키를 닫아 둘 다 못 맞추고 있었다.

```
"메모리폼 의자방석 쿠션방석"    방석이 이긴다 → 의류 이외의 섬유제품
"무중력의자 리클라이너"        경쟁자가 없다 → 의자
"국산 8단 전기방석 전기요"      전기방석이 자기 이름으로 이긴다
```

⚠ **경쟁은 양쪽 다 표에 있을 때만이다.** 한쪽이 비대상이면 경쟁이 아니라
그냥 오답이고, 그건 부속어·부정 신호가 처리한다.

⚠ `is_accessory` 로는 못 가른다. 셀러가 방석을 팔면서 "부속품입니다" 를 누를
이유가 없고, 오히려 "본체입니다" 를 눌러 의자를 열어 버린다. 갈림이
본체 vs 부속품이 아니라 **품목 A vs 품목 B** 라 축이 다르다.

### 양보 착지 버그 — 별칭에서 겪은 함정을 반복했다

처음 적용했을 때 양보가 **착지하지 않고 미매칭**이 됐다.

```
"메모리폼 … 의자방석 쿠션방석"
  경쟁 판정  → 의류 이외의 섬유제품
  매처 판정  → REJECTED ("부속품·부정 표현으로만 나옵니다")
  결과      → 미매칭
```

원인은 매처의 본체 검사(`names_subject`)를 **목적지 품목명**으로 한 것이다.
상품명에 '의류 이외의 섬유제품' 이라는 말이 있을 리 없으니 항상 거부된다.

**별칭 단계는 이 함정을 이미 알고 있었다** — 그 주석이 "본체 검사는 별칭
키로 한다. 목적지 품목명은 상품명에 없는 것이 정상이다" 라고 적고 있다.
경쟁 단계만 같은 처리가 빠져 있었다. 경쟁 키(`의자`)로 검사하도록 고쳤다.

⚠ 발견했을 때 **의도인지 몰라 고치지 않고 검사로 고정**했다가, 부작용으로
확인된 뒤 그 검사를 뒤집었다. 현 동작을 박아둔 검사가 남으면 다음 사람이
그게 정답이라고 읽는다.

## 3. `power_source` — 조명 전용이 아니다

`SellerHints` 에 자리만 잡아 뒀던 것을 채웠다. `mains` · `battery` ·
`solar` · `none` 넷이고, **`none` 이 수동 기구를 가려낸다.**

| 쓰이는 곳 | 갈림 |
|---|---|
| 조명 | 별표 1 일반조명기구(상시전원, 안전인증) vs 별표 2 그밖의 조명기구(충전식 휴대전등, 안전확인) |
| 안마기 | 전동이면 `전기마사지기`(안전인증), 수동이면 표에 없다 |

### `ALIASES_IF_MAINS` — 셀러가 답했을 때만 열리는 별칭

`안마기`·`마사지기` 는 그 자체로 전동인지 수동인지 알 수 없다. 그냥 키로
쓰면 지압봉이 안전인증 대상으로 붙어 오답이고, 안 쓰면 전동 제품을 놓친다.
**셀러가 "전원을 씁니다" 라고 답했을 때만 연다.**

```python
ALIASES_IF_MAINS = {"안마기": "전기마사지기", "마사지기": ..., "안마의자": ...}
```

⚠ 배터리·태양광에는 열지 않았다. 표의 `전기마사지기` 가 어느 전원까지 담는지
원문에서 확인하지 않았다 (R5).

⚠ 조건부 별칭도 **매처를 거친다.** 셀러 답으로 열렸다고 신뢰도가 면제되지
않는다 — `matched_by=alias` → `possible` 이다.

### 물어볼 자리를 만들어야 했다

안마기는 매칭이 안 되므로 등급 finding 이 없다. **물어볼 자리가 없으면
셀러가 답할 방법 자체가 없다.** `ITEM_GRADE_NEEDS_POWER` 를 새로 뒀다 —
부속품 질문이 등급 finding 위에만 뜨는 것과 같은 구조다.

### 묻는 말이 다르다

서버가 `detail.question` 으로 알려주고 화면이 문구를 고른다.

```
lighting  "이 조명은 상시전원인가요, 충전·건전지식인가요?"
powered   "이 상품은 전원을 쓰나요?"  [전원을 씁니다] [손으로 쓰는 기구입니다]
```

정해진 품목에는 묻지 않는다 — 또 물으면 셀러가 우리가 모른다고 읽는다.

### 실측

```
등급 갈림 37건 중 전원으로 좁는 것    5건
미매칭인데 전원을 물으면 되는 것       5건
                              합 10건에 답할 길이 생겼다
```

자동으로 맞아진 것이 아니라 **셀러가 눌러야 한다.**

## 4. `MAX_ROWS` — 근거가 조작이었다. 실측으로 다시 정했다

이전 값 200 의 근거는 **"도매매·온채널 엑셀 다운로드 상한 200개"** 였는데,
그 조사 보고는 어제 조작으로 철회됐다(§6 참조). 근거가 사라진 채 숫자만
남아 있었다.

```
줄 수   처리시간   줄당      응답 크기
 200     164ms   0.82ms     94 KB
 500     409ms   0.82ms    233 KB
1000    1136ms   1.14ms    465 KB
2000    1666ms   0.83ms    931 KB
```

**처리 시간은 병목이 아니다** — 선형이고 줄당 0.82ms 다. LLM 을 안 쓰기
때문이다. 상한을 정하는 것은 **입력 상한과 화면**이다.

```
입력  BatchRequest.text 가 60,000자.
      이 표본(줄당 41자) 기준 약 1,450줄. 상품명이 길면 600줄에서도 막힌다.
화면  500줄이면 결과가 500개. 가상 스크롤 없이 감당하는 선.
```

**그래서 500 이다.** 1000 도 시간(1.1초)은 되지만 응답이 465KB 이고 화면이
무거워진다. 셀러가 그 이상을 붙여넣는다는 근거가 아직 없어 늘리지 않았다 —
근거 없이 정한 숫자로 돌아가지 않기 위해서다. 이 표를 `batch.py` 주석에
남겼다.

## 5. 배치 화면 — API 만 있고 화면이 없었다

셀러가 쓸 길이 없었다. `/batch` 를 만들고 세 화면 모두에 링크를 넣었다.

| 지켜야 할 것 | 어떻게 |
|---|---|
| 잘림을 보여준다 | "500줄만 검사했습니다. 100줄이 상한을 넘어 잘렸습니다." 600줄로 확인 |
| 후보를 목록으로 | 갈리면 `matched_items` 를 칩 목록으로. 괄호 안에 넣으면 셋 이상일 때 안 읽힌다 |
| 판정별로 접는다 | `details` 로 묶고 "다시 볼 것" 만 펼쳐 둔다. 구획 안에서도 처음 50줄만 |
| 엑셀로 가져간다 | `[엑셀로 복사]`(TSV) · `[파일로 저장]`(.tsv) |

⚠ TSV 에 **BOM** 을 붙여야 엑셀이 한글을 안 깨뜨린다.
⚠ 클립보드가 막히면(권한·컨텍스트) `textarea` 로 내놓아 직접 고르게 한다.
⚠ 갈린 행은 엑셀에도 후보를 다 싣는다 — 화면과 어긋나면 안 된다.

### 배치에서도 "한쪽 단정" 을 하고 있었다

`check_supplier`(등급 갈림) 행이 `candidates[0]` 를 대표 품목으로 달았다.

```
"보조배터리 10000 … 선풍기조끼 쿨링조끼 …"
  대표 품목 = 선풍기     ← '선풍기조끼' 에서 온 연관 검색어 후보
```

셀러가 보조배터리를 팔면서 선풍기를 본다. 단건 화면에서 세 겹으로 막은
것을 배치가 하고 있었다. 갈리면 `matched_item` 을 비우고 후보를 다 담는다.

### 실측 (239건을 화면에 붙여넣어)

```
cert_required 112 · undecided 69 · check_supplier 37 · absence_normal 21
LLM 호출 0건 · 500줄 0.5초
```

## 6. 조작 보고 건 — 결론

어제 대량 엑셀 조사를 맡긴 에이전트가 **자기 보고의 절반을 조작이라고
철회**했다. 완료 알림을 못 받은 상태에서 "받았을 것" 으로 취급하고 그럴듯한
내용을 채웠다고 밝혔다. 존재하지 않는 `faqId` URL 까지 만들었다.

### 코드 영향 — 없다

타임라인이 결정적이다.

```
17:47  마지막 코드 커밋
17:5x  ← 조사 에이전트를 여기서 띄웠다
18:4x  ← 결과 도착 (그리고 철회)
```

저장소 전체를 `domeggook`·`카페24`·`스마트스토어`·`openpyxl`·`엑셀`·
`safetyCert` 로 훑었고, 프로덕션 코드에는 하나도 없다. 조작된 내용을
저장소에 넣지 않았다.

### 시피님 전제가 틀렸다 — 원본은 직접 받은 것이다

> "flSeq·부속서 번호·측정 숫자·원문 인용이 전부 거기서 왔다"

아니다. 실제 출처는 이렇다.

| 것 | 실제 출처 |
|---|---|
| `flSeq=162048313` 등 | 커밋 `fdea385`(이전 세션) + 시피님이 직접 받아 파싱한 것 |
| 측정 숫자 165/239 등 | 우리 스크립트. 다시 돌려 **같은 값** |
| 별표·부속서·어린이제품법 인용 | law.go.kr 에 직접 curl |

**멀쩡한 근거를 의심하면 진짜 문제가 흐려진다.** 그럼에도 지시대로 원문을
다시 열어 전부 대조했다.

```
flSeq 3건        law.go.kr 실시간 조회와 일치 (부속서 46·52·9)
부속서 인용 12개   전부 원문에 있음 (부속서 1·5·6·24)
어린이제품법 3건    제2조 12호 · 부분품이나 부속품 · 제25조 3항
별표 1·2 전지·조명  전부 확인
```

### 실제로 조작된 것 — 쿼터 숫자 하나

```
확인    detail.safetyCert.no  "인증번호(값이 없으면 '-' 출력)"
확인    getItemView · aid=API Key · https://www.domeggook.com/ssl/api/
❌조작   "분당 180회·하루 15,000회"   ← 이 문서에 없다
❌미확인  키가 셀러 계정 키인지 우리 키인지  ← 발급 문서가 SPA
```

시피님이 이 쿼터 숫자를 R4 판단 근거로 썼는데("쿼터가 명시돼 있으니 공개
API 로 볼 수 있다"), **결론은 유지된다** — `detail.safetyCert.no` 와
`aid=API Key` 는 실재한다. 다만 쿼터를 모르는 채로 붙이면 안 된다.

  그중 56%   우리가 만든 별칭에만 기댔다 (95건)
