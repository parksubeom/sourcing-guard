## 1. [제출-1] 제출문을 기준선 하나에 묶었다

### 1.1 ⚠⚠ 찾은 것 — 제출문이 **자기가 선언한 원칙을 다음 문장에서 어겼다**

제출문 §2 1000자판:

    단건: "사람이 검수한 쌍만 세면 **95건(70.4%)**, 검수하지 않은 18건을 모두
           정답으로 가정한 상한은 **113건(83.7%)**. **두 값을 함께 적는 이유는
           검수 전 숫자를 검수된 숫자처럼 쓰지 않기 위해서입니다.**"
    배치: "대량 검사 경로는 **82.2%** 입니다."          ← 한 값뿐

**82.2% 는 상한이다.** 검수 분리로 다시 재니:

    배치 · 상품명만 · 분모 135
      ① 검수된 정답  96 (71.1%)      ② 미검수 15
      ③ 상한        111 (82.2%)      ④ 0 · ⑤ 2

원칙을 선언한 바로 다음 문장이 그 원칙을 어기고 있었다. **심사 서류다.**

왜 안 잡혔나: 숫자가 두 곳에 따로 있었다 - `test_item_grades` 에 하드코딩된
`ok == 111` 과 제출문의 "82.2%". 둘을 잇는 것이 없었다 (§6).

### 1.2 고친 것

`scripts/audit_tally.BASELINE_BATCH` 를 만들어 **한 곳**으로 모으고
`batch_tally()` 로 재생한다. 단건 재생과 **같은 `tally`** 를 쓴다 - 집계를 다시
적으면 두 경로가 갈린다(2026-09-08 에 구현이 셋이라 77.8% 를 적었던 일).

제출문 §2 를 고쳤다:

    후: "데모와 같은 단건 경로 기준이고, 대량 검사 경로도 같은 방식으로
         **96건(71.1%) · 상한 111건(82.2%)** 입니다."

### 1.3 글자 수 — 1,138자였다

[G-2] 가 넣은 `count_submission_chars.py` 가 "AI 활용 방식 1000자판 1,138자"
를 찍었다. 표에는 964 라 적혀 있었다 - **손으로 센 값이 174자 어긋나 있었다.**

배치를 두 값으로 고치면 더 길어지므로 같이 줄였다: **1,138 → 998자.**
뺀 것은 중복 수식어뿐이고 R1·R2·R3·R3-b·규칙DB·전수검수는 그대로 뒀다.

    해결하려는 문제   197 / 497 / 964
    AI 활용 방식     158 / 412 / **998**
    사용한 AI 도구    183 / 391 / 925

⚠ 폼의 실제 계산 방식은 **아직 모른다**(로그인 확인 전). 우리 계산은 공백
  포함이라 보수적으로 큰 쪽이다.

### 1.4 ⚠⚠ 옛 가드가 **맞는 값을 막고 있었다** — §6 의 거울상

`test_docs` 에 `for stale in ("71.1%", "40.9%", "96건")` 이 하드코딩돼 있었다.
9/7 시절 낡은 값을 막으려던 것인데, **그 셋 중 둘이 오늘 살아났다** - 배치의
검수된 정답이 정확히 96건(71.1%)이다.

    §6        검사가 기대값을 **현재 출력**에 맞춰 쓰면 버그를 고정한다
    거울상    한때 틀렸던 값을 **영원히 틀린 것**으로 적어 두면, 그 값이
              옳아졌을 때 가드가 문서를 거짓말하게 만든다

고친 방향은 같다 - **기준선에서 살아 있는 값을 빼고 나머지를 막는다.** 목록을
손으로 유지하지 않는다. 소유자는 `tests/test_submission_numbers.py` 하나다.

### 1.5 자기 주석 함정 — **여섯 번째**

새 가드가 제출문 전체를 훑다가 "이 자리에 `71.1% / 40.9%` 가 남아 있었다" 는
**정정 기록**에 걸렸다. 검사 범위를 **실제 제출되는 답변 본문**(`### N자` 절)
으로 좁혔다 - 정정 이력에는 옛 값이 일부러 있어야 한다.

### 1.6 새 검사 6건 — 둘은 잡는 것을 확인했다

    배치 기준선이 재생값과 같다
    단건·배치 **둘 다** 두 값을 적는다
    배치 숫자에 "상한" 이라는 말이 붙어 있다
    세 항목 × 세 길이가 **전부 제한 안**이다
    제출되는 본문에 은퇴한 정답률이 없다 (살아 있는 값은 기준선에서 뺀다)
    랜딩 가드가 기준선을 본다 (같은 단정을 두 파일에 적지 않는다)

  확인: 글자를 60자 늘리니 "AI 활용 방식 1000자판 = 1059자 (59 초과)" 로 실패.
       배치를 상한 하나로 되돌리니 "배치 의 검수된 정답 96건(71.1%) 이 제출문에
