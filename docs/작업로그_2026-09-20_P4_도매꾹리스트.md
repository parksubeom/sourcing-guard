## 실호출 회차

### 도매꾹 Open API — 86회

    탐침                    1   썸네일 URL 호스트를 보려고 목록 1회
    collect --dry-run      12   목록 8 + 상세 4 · 파싱 검증
    collect 1차            12   목록 8 + 상세 4
    collect 2차            12   목록 8 + 상세 4   ← 번호 전부 조회로 고친 뒤
    screen ×6              48   목록 8 × 6
    RED 이유 되찾기          1   상세 2건을 한 번에

⚠⚠ **screen 을 여섯 번 돌렸다. 넷은 내 실수다** - 적어 둔다:

    1회  그물이 너무 넓었다. "품목 이름의 낱말이 상품명에 있으면 의심" 으로
         셌더니 「놀이방매트 → 매트류」 같은 **정상 매칭 40여 줄**이 걸렸다
    2회  코드 오류(NameError)로 목록을 받은 뒤 멈췄다
    3회  좁힌 판. 이때 화면 출력은 맞았는데 **파일이 안 써졌다** - 블록을
         고치면서 쓰는 코드를 같이 지웠고, 함수가 `None` 을 돌려주는데
         `SystemExit(None)` 이 종료코드 0 이라 **조용히 성공으로 보였다**
    4회  쓰는 코드를 되살린 뒤. `| head -8` 로 받아 파이프가 먼저 닫혀
         쓰기 전에 죽었다
    5회  제대로 돌았다
    6회  쓴 뒤에 스스로 단정하는 `write_note` 를 넣고 확인

  ⚠ 3회가 이 저장소의 그 패턴이다 - **실패하지 않는데 아무것도 안 하는 것.**
    `main()` 이 `screen_titles()` 의 반환값을 그대로 `SystemExit` 에 넘기므로
    `None` 은 성공이다. 쓰는 스크립트는 쓴 뒤에 **그 파일이 성한지 스스로
    단정**해야 한다 (§6 - `app.css` 머리를 부순 그 자리와 같은 교훈).

## ⚠⚠ LLM 30회를 더 쓴 이유

1차 수집이 상품마다 **첫 번호만** 국표원에 조회했다. 상품 48182475 는 번호가
셋이고 **셋째가 안전인증취소** 였는데, 첫 번호가 적합이라 미리 거르는 그물을
그대로 통과했다. 스캔이 RED 로 잡아 화면에는 안 올라갔지만, 사본의 `cert`
필드가 "이 상품의 인증상태" 인 것처럼 **첫 번호만** 적고 있었다 - 자료가
거짓말을 하는 상태다. 번호 전부를 조회하도록 고치고(`certs` 배열) 다시 쟀다.

§6 "가드를 만들 때 반대 방향도 한 줄로 재라" 의 또 한 번이다. 주석이 걱정한
것은 "취소된 인증을 화면에 올리는 것" 이었고, 실제 구멍은 **번호가 여러 개일
때 첫 번호만 봤다** 였다.
